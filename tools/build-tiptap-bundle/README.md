# Canvas 富文本引擎构建与回归测试

运行环境：Node.js 18+（测试所用 jsdom 要求 Node.js 18+）。

```sh
cd tools/build-tiptap-bundle
npm ci
npm test
npm run build
```

`entry.js` 封装 Tiptap，`src/` 保存画布定制节点；构建产物为
`Bookmark-Canvas-main/history_html/vendor/canvas-editor-tiptap.bundle.js`，发布时需要一并更新。

## 数据与生命周期约定

- 文档未修改，或撤销回初始状态时，返回原始 Markdown，避免仅打开编辑就改写源码。
- HTML 实体是合法 Markdown 内容，不再对所有文档自动解码。旧的、已经被双重转义的数据需要单独确认后迁移，不能从字面文本猜测。
- `details` / `summary` 使用真实 Schema 节点，保存折叠结构、富文本内容和 `open` 属性。
- 简单表格保存为 GFM，并转义整个单元格中的 `|`；合并单元格、多段落、列宽等结构保留 HTML。
- 静态待办通过同一解析器的源码行映射更新；混有 HTML 待办而无法直接定位时，更新文档节点后序列化，避免勾错其他任务。
- 临时备注通过冒泡的 `focusout` 和画布外部点击提交；点击工具栏不退出编辑。
- 普通模式下，空白卡、临时备注和永久备注进入编辑时自动打开格式工具窗；显式点击格式按钮只切换一次，关闭按钮不触发编辑器初始化。卡片全屏不自动打开，但可手动打开/关闭，空白卡与备注使用同一套定位适配。
- 格式工具窗按画布可见区域实测宽度适配：常规按钮 22px、间距 2px；窄时先切到 20px 按钮、1px 间距的紧凑排布，再按实测宽度缩小到不低于 80%，仍放不下才换行，避免最后一个按钮单独落在第二行。窗口/侧栏尺寸、全屏状态和卡片布局缩放变化后重新定位，不修改正文或卡片缩放设置。支持 Popover API 的 Chrome/Edge 使用手动 top layer，保留原 DOM 事件归属并越过卡片裁切和目录/锚点侧栏层叠上下文；不支持该 API 时保留 DOM 内定位回退。字体色盘、说明与格式子菜单保持可见可点，关闭/销毁时回收监听器和顶层浮窗。
- 外层悬浮操作工具窗同步收紧：按钮 26px、间距 3px；空白卡全屏实际宽度不超过 400px 时，使用容器查询切到 22px 按钮、1px 间距，并收紧缩放控件，不影响正文缩放或省略任何操作。
- 格式工具窗 `×` 左侧提供 `?`“编辑说明”，使用无边框、左对齐紧凑列表，操作、快捷键、语法各自共用对齐起点，语法统一左对齐。保留各格式快捷键和 Markdown/HTML 样例；黄色操作名只写“恢复普通输入”，中间为 Ctrl/Cmd+\，片段末尾 `→` 放在右侧语法分区。不恢复平台小字或其他通用说明。非模态说明不改选区、格式或正文，Esc 不穿透到备注取消/提交，输入法组合优先；销毁时清理弹层和监听器。
- `src/plain-typing.js` 注册编辑器内的 `setPlainTyping` 命令和统一快捷键：无选区时显式清空下一输入标记（含链接延续），不改已有文字、块结构、卡片字号或光标，不增加内容撤销步骤或持久化写入。有非空/节点选区、只读或输入法组合期间不处理；不新增按钮，不调整重入边界规则。
- 同一扩展的 `exitInlineFormatAtEnd` 在已有格式片段末尾处理一次普通 `→`，无字符退出七类行内样式及链接延续；再次按键恢复导航。格式内部、刚开启未输入、显式普通输入、修饰键、非空选区、输入法组合、代码块及混合/RTL 文字保持原生导航。`src/canvas-starter-kit.js` 只关闭链接/代码原生插空格的 `exitable`，不修改 schema 或组合内容解析。
- 格式按钮的持续选中边框读取 Tiptap 实际状态；同时监听文档、选区和待输入格式变化，支持按钮/快捷键、已识别语法、撤销重做，不另做逐行语法扫描。未闭合语法不会提前激活；菜单打开与格式启用分开标记。不新增双空格退出。
- 工具按钮和格式快捷键采用行内单选：加粗、斜体、下划线、高亮、删除线、行内代码、字体颜色，后选的替换当前选区内或下一次输入的旧格式；点已启用的格式仍为关闭。清除颜色不会恢复被替换的旧格式。
- 手写 Markdown、富文本/Markdown 粘贴及导入保留用户明确表达的组合格式，不按固定优先级清洗。单选约束只在执行格式命令时作用于当前选区或后续输入；手输语法仍使用 Tiptap 原有自动转换和 Backspace 回退规则。
- 已有数据的多重格式不在加载/刷新时自动清洗。标题、列表、对齐不属于行内单选组；普通格式切换不主动清除链接（行内代码原本不支持链接的规则保持不变）。统一普通输入命令只退出后续链接延续，不删除原链接。这是一项交互约束，不代表对任意历史组合的序列化问题做了全量修复。
- 虚拟化卸载使用 `__cleanupCanvasNodeTiptapInstances(element, { commit: true })`；删除、导入替换等路径使用默认销毁，不额外写回已删除内容。所有路径都解绑永久备注的 document 监听器。

## 测试范围

测试使用 Node 内置测试运行器和 jsdom。引擎由当前源码即时打包，备注测试执行生产函数和备注渲染片段；只隔离扩展存储服务，不依赖手工复制的编辑逻辑。

覆盖失焦/工具栏/清空/销毁、首次点击与备注工具窗初始化、卡片全屏手动开关/横向宽度适配/缩放补偿/顶层浮窗清理、说明的左对齐/字面语法/选区格式保护、Esc 与生命周期、统一普通输入和片段末尾方向键退出的多格式/链接/块结构/平台/选区/组合输入/撤销和无脏写入、按钮持续选中和事务状态同步、七类行内格式两两替换/选区边界/输入规则/剪贴板往返、实体和代码保护、折叠块、表格竖线与复杂结构、引用/嵌套/HTML 待办、裸 URL、图片、中文加粗，以及重复解析插件幂等性。

jsdom 不能替代真实浏览器的布局、中文输入法候选、拖选和大画布性能验收。发布前仍需在加载扩展的浏览器中验证这些交互。

个人手工验收步骤、通过标准和可导入样例见 [`docs/画布富文本-个人手工测试方案.md`](../../docs/画布富文本-个人手工测试方案.md)。
