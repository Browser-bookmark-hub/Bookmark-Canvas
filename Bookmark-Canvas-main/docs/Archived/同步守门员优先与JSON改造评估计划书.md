# 同步守门员优先与 JSON 改造评估计划书
> 返回索引：[docs/README.md](./README.md)
> 关联主计划：[存储收敛与JSON模式总顺序计划书](./存储收敛与JSON模式总顺序计划书.md)

## 1. 目标
- 先解决同步链路中最影响体感和正确性的问题：误判 dirty、同步后 dirty 不清、远端未变化仍做重处理、手动同步耗时偏高。
- 先做轻量且可落地的文件级判定，不先启动永久栏目/临时栏目的大规模底层重构。

## 2. 执行顺序（本计划）
1. 第一执行项：布局壳收口 + 同步守门员（单文件签名判脏）
2. 第二执行项：评估“永久栏目 / 临时栏目是否改成 JSON 模式”，评估后再决策是否立项

## 3. 第一执行项：同步守门员（立即实施）
### 3.1 范围
- 守门员只放在“存储写入入口”和“同步读写入口”。
- 判脏粒度按单文件/单实体，不按整包全局。
- 同步前只对“当前正在编辑中的卡片”做一次兜底 flush，不做全量重刷。

### 3.2 规则
- 每个实体维护最小状态：`signature`、`lastSyncedSignature`、`dirty`。
- 任何写入经过守门员：
  1. 先做该实体的规范化序列化；
  2. 计算签名（hash）；
  3. 与上次签名比较；
  4. 仅当签名变化时置脏并更新签名。
- Push/Pull 成功后，只清本次成功实体的 `dirty`，不清其他实体。
- 远端签名未变化时，跳过对应实体的解析、应用和重建。

### 3.3 验收
- 面板 dirty 与实际变更一致，不再出现“push 成功但 dirty 不清”。
- 未改动实体不再被误标脏。
- 远端未变化时不再走整段重解析。
- 手动同步体感明显下降，目标进入 5-10 秒区间（按实际数据再细化）。

## 4. 第二执行项：是否改永久/临时为 JSON 模式（先评估）
### 4.1 评估结论必须覆盖
- 收益：同步速度、代码复杂度、长期维护成本。
- 风险：右键菜单、懒加载、三模式（`visual / visual-no-icon / json`）兼容。
- 迁移：数据迁移成本、回滚方案、灰度步骤。

### 4.2 决策门
- 默认策略：不直接前置大改。
- 只有评估结论明确“收益显著且风险可控”才进入实施。
- 若不满足条件，保持现有永久/临时主结构，仅继续增强守门员与协议层。

## 5. 非目标（本轮不做）
- 不在本轮重写永久栏目和临时栏目的全部运行时结构。
- 不在本轮强制切换全部模式到 JSON-only。
- 不为未进入执行范围的模块做连带式改造。

## 6. 当前代码级风险全景（已实查）
### 6.1 Dirty 判定与清理链路风险
- “同步进行中本地编辑兜底”目前会在触发时把永久/临时/空白/画布整体重新置脏，容易出现同步成功后又被二次置脏的体感。
- Dirty 原因存在默认兜底分支，未显式声明粒度时会落到较宽范围标记，容易放大改动面。
- 空白卡片中“插件卡片”与“原生 text 镜像卡片”在判脏到文件映射上并非完全同一套路，存在精度不一致风险。
- 面板展示的脏摘要与实际上传候选集合来自不同层的汇总，可能出现“显示脏”与“实际未上传”不一致。

### 6.2 存储写入入口分散风险
- 临时/空白主体通过一个主入口保存，但永久栏目的位置、副本、说明等由多组写入入口分别处理。
- 同一个功能动作可能同时触发多个存储键与画布文件变化，缺少单一事务边界，容易出现部分成功、部分未对齐。

### 6.3 同步流程风险
- 手动同步当前默认走“全候选比较”策略，即使只改一个卡片，也会先构建整包导出视图再判定。
- 未命中快速路径时，全量同步仍会先拉取并解析远端托管文件集合，远端未变化也有重处理开销。
- 拉取应用链路同时包含旧键回写、临时状态应用和 DOM 重建，多步骤串联导致中间态可见风险更高。

### 6.4 模式与迁移风险
- 三模式并行加上格式迁移分支，会引入额外分叉；一旦和普通同步并发，容易扩大影响面。
- 格式切换会主动扩大脏范围，这一策略在正确性上保守，但在性能和可解释性上成本较高。

### 6.5 恢复与并发风险
- 恢复锁、冲突待处理、运行队列和脏标记是并行状态机，边界不清时容易互相覆盖状态。
- 同步期间用户继续操作会被后置逻辑再次标脏，若粒度不精确，会掩盖本次同步已成功的事实。

### 6.6 性能风险
- 上传链路每次都要构建导出文件集合并做哈希/差异判定，大画布下 CPU 与序列化开销明显。
- 拉取计划构建同样会做本地导出视图，形成“上传重、拉取也重”的双侧成本。
- 大包提交存在长等待窗口，虽然有进度心跳，但体感上仍容易超出 5-10 秒目标。

## 7. 第一执行项的风险收敛门（先过门，再提速）
1. 入口收口门：所有会影响同步实体的本地写入必须经过守门员入口，不再允许散落式改脏。
2. 精度门：取消宽兜底判脏；每个原因都必须显式给出实体级 dirty patch；“同步中变更”改为记录精确 patch，不再整包置脏。
3. 映射门：建立完整的“实体 -> 文件”映射，覆盖永久主栏/副本、临时栏目、插件空白、原生 text 镜像、画布文件。
4. 清理门：Push/Pull 成功后只清本次成功实体，且面板摘要要与实际上传/拉取结果一一对应。
5. 快路门：远端未变化时跳过重解析；手动小改动在安全前提下不再默认走全候选全比较。
6. 可观测门：面板同时展示“本地脏实体、实际上传路径、同步后清理结果”，三者必须一致。
