# Bookmark-Canvas 后台同步与不一致处理计划书（V1）

## 1. 目标

- 在页面/侧边栏关闭时，后台仍可进行轻量同步检查。
- 当检测到“云端版本与本地不一致”时，按用户策略处理。
- 新增清晰的角标状态规则，减少用户误解。

## 2. 当前现状（基线）

- 当前自动同步与定时推送/拉取运行在页面脚本中（非后台常驻）。
- 当前判断已包含：
  - 云端版本（SHA）比较
  - 本地/云端快照哈希比较
  - 时间与大小兜底
- 状态页已展示：云端版本（SHA）与本地哈希。

## 3. 本次要做的功能范围

### 3.1 后台检查（页面关闭仍可运行）

- 使用 `service worker + chrome.alarms` 执行后台轻量检查。
- 检查优先采用“元数据优先”：优先读取导出根目录（默认 `书签画布`，若配置仓库基路径则为其下对应子目录）的路径级最新提交信号，必要时再读取完整内容。
- 后台维护连续无变化计数（idle streak）：
  - 连续 2 次无变化后，降低频率或暂停一段时间。
  - 一旦检测到新差异或本地新编辑标记，立即恢复常规频率。

### 3.2 不一致处理策略（新增按钮）

- 在策略页中，放置于“启动时自动拉取”上方。
- 新增配置项：`云端不一致处理策略`。
- 选项：
  1. 自动拉取
  2. 弹窗提示
     - 与云端对齐（拉取）
     - 以本地为主，覆盖云端（推送）

### 3.3 页面恢复与执行策略

- 后台检查发现不一致时，先写入 `pendingMismatch` 状态。
- 若策略是“自动拉取”：按最终实现方案执行自动拉取（或标记后页面打开自动执行）。
- 若策略是“弹窗提示”：不自动改数据，页面打开后弹出二选一处理。

## 4. 角标规则（纳入本计划）

- 复用现有角标体系，不新增第二套角标入口。

### 4.1 显示样式

- 平时：蓝色。
- 有待处理内容（有东西）：橙色。

### 4.2 数字/符号规则

- 若“永久栏目标识（数字）”开启：显示数字角标（蓝/橙）。
- 若“永久栏目标识（数字）”关闭：未检测到不一致时显示蓝色横杠；检测到不一致时显示橙色提示符号。

### 4.3 “有东西”的定义

满足任一条件即视为“有东西”：

- 本地有未同步变更（dirty）。
- 检测到云端不一致（`remoteDirty` / `pendingMismatch`）。
- 队列中有待执行任务或正在同步。

恢复蓝色条件：

- 无本地未同步、无云端不一致、无待执行任务、同步空闲。

## 5. 数据与状态建议

- `syncRuntime` 扩展字段（建议）：
  - `lastRemoteSha`
  - `lastLocalHash`
  - `lastSuccessAt`
  - `pendingMismatch`
  - `idleStreak`
  - `nextCheckAt`
- `syncSettings` 扩展字段（建议）：
  - `mismatchPolicy`: `auto_pull` | `prompt`
  - `backgroundCheckEnabled`
  - `backgroundCheckIntervalMinutes`
  - `backgroundCheckCooldownMinutes`

## 6. 实施阶段

### 阶段 A（先落地，低风险）

- 接入后台 `alarms` 检查循环。
- 完成不一致策略按钮与配置持久化。
- 实现 `pendingMismatch` 标记、状态展示与角标蓝/橙切换。
- “弹窗提示”策略在页面打开时触发处理弹窗。

### 阶段 B（增强）

- 细化后台自动拉取执行链路。
- 增加更智能的降频/恢复策略（按连续稳定次数动态调整）。
- 增加调试日志与状态可视化（最近一次后台检查、命中策略等）。

## 7. 验收标准

- 页面和侧栏都关闭时，后台仍能按计划执行检查。
- 检测到不一致后，策略分流正确：
  - 自动拉取：自动处理成功或明确失败状态。
  - 弹窗提示：打开页面后出现“与云端对齐 / 以本地覆盖云端”。
- 角标状态正确：
  - 平时蓝色；检测到不一致时橙色。
  - 数字关闭时，空闲显示横杠，检测到不一致显示提示符号。
- 状态页可看到云端版本与本地哈希，并能反映待处理状态。

## 8. 风险与注意事项

- MV3 `service worker` 非常驻，必须依赖 `alarms` 与事件驱动。
- 后台直接改本地数据需谨慎，优先采用“标记 + 页面确认”策略降低误覆盖风险。
- 冲突策略需要与现有“本地优先/云端优先/默认 Git”保持一致。
