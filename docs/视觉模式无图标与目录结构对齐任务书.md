# 视觉模式无图标与目录结构对齐任务书

> 返回文档索引：[docs/README.md](./README.md)

## 1. 任务背景

当前 Bookmark-Canvas 的 Obsidian 导出 / 同步能力，已经在同步链路中支持 3 种导出表现模式：

- `editable`
- `visual`
- `visual-no-icon`

但手动导出入口与目录结构仍未完全对齐，主要存在两类问题：

1. `visual-no-icon` 只在同步导出侧完整接入，手动导出 UI 与普通导出流程尚未完全对齐。
2. 导出后的目录结构尚未完全和插件内“目录栏”的分类语义对齐，尤其是：
   - 临时栏目需要稳定地体现为两类目录。
   - 空白栏目也需要稳定地体现为两类目录，而不再只是“代码里有两类对象、导出层只有一类文件夹”。

本任务的目标不是修改同步策略，而是统一“文件结构表现层”和“模式表现层”。

## 2. 任务目标

### 2.1 视觉模式无图标对齐

将 `visual-no-icon` 提升为与 `visual`、`editable` 同级的正式导出模式，做到：

- 手动导出可选。
- 同步导出可选。
- 文档说明明确。
- 导入逻辑保持内容驱动，不依赖模式名恢复。

### 2.2 目录结构对齐

将导出 / 同步目录结构与插件侧栏分类语义尽量对齐，重点落实为：

- 临时栏目：两个子文件夹。
- 空白栏目：两个子文件夹。

要求用户在导出目录中，可以直接看出这些分类，而不是只能在插件 UI 中理解。

## 3. 当前状态

### 3.1 导出模式

- 同步导出：已支持 `visual-no-icon`。
- 手动导出：当前只明确暴露 `visual` 与 `editable`，尚未与同步导出完全齐平。
- 导入：按实际内容解析，不应依赖“模式名”。

### 3.2 临时栏目目录

当前临时栏目目录已经基本体现两类：

- `Temporary/General Chain/`
- `Temporary/Special temporary/`

中文路径对应：

- `临时栏目/常规链式/`
- `临时栏目/特殊临时栏目/`

因此临时栏目部分属于“确认并固化”，不是从零开始设计。

### 3.3 空白栏目目录

当前空白栏目还不是“两个正式文件夹”，而是两类对象混合存在：

1. Markdown 空白栏目
   - 导出为 `Blank/*.md` 或 `空白栏目/*.md`
2. Canvas 原生文本节点
   - 不导出为独立 `.md`
   - 仅保留在 `.canvas` 中

因此空白栏目目前属于“两类对象”，还不是“两类目录结构”。

## 4. 本任务的正式范围

### 4.1 范围内

- 手动导出 UI 增加 `visual-no-icon`
- 手动导出生成逻辑与同步导出保持一致
- 说明文档中补齐 3 种模式定义
- 临时栏目目录结构确认、命名统一
- 空白栏目目录结构拆分方案设计与落地
- 导入 / 同步拉取对新增目录结构的识别兼容

### 4.2 范围外

- 同步冲突策略变更
- 首次同步策略变更
- 永久栏目拉取方式变更
- 书签树协议本身变更
- skill 打包与外部发布

## 5. 目录结构建议

### 5.1 临时栏目

建议继续明确为：

- `Temporary/General Chain/`
- `Temporary/Special Temporary/`

中文导出可对应：

- `临时栏目/常规链式/`
- `临时栏目/特殊临时栏目/`

要求：

- 手动导出与同步导出完全一致。
- 导入时按目录优先识别临时栏目类型。

### 5.2 空白栏目

建议从“对象双轨”提升为“目录双轨”。

推荐拆分为：

- `Blank/Markdown/`
- `Blank/Native Text/`

中文导出可对应：

- `空白栏目/Markdown/`
- `空白栏目/原生文本/`

说明：

- `Markdown`：导出为独立 `.md` 文件的空白栏目。
- `Native Text`：原生 canvas text node。

若最终决定不把原生文本导出为独立文件，也必须在目录方案与说明文档中明确：

- 为什么它仍属于“空白栏目第二类”
- 为什么它只存在于 `.canvas`
- 导入 / 同步如何恢复

换句话说，本任务必须解决“用户能不能从导出目录中看懂空白栏目两类”的问题。

## 6. 导入与同步约束

### 6.1 导入约束

- 导入逻辑必须优先按内容解析，而不是按模式名解析。
- 新增目录层级后，导入识别应兼容旧路径与新路径。
- 不允许因为目录细分导致旧导出包失效。

### 6.2 同步约束

- 同步导出目录结构必须与手动导出一致。
- 同步拉取时，新增目录结构必须被识别为同一类语义对象。
- 不允许“手动导出一种结构、同步导出另一种结构”。

## 7. 文档与说明要求

本任务完成后，以下文档需要同步更新：

- 导出包内说明文件
- `docs/README.md`
- 导入/导出/同步格式说明

其中必须明确写清：

- 三种导出模式的差异
- 临时栏目两类目录
- 空白栏目两类目录
- 导入时的识别规则

## 8. 验收标准

### 8.1 视觉模式无图标

- 手动导出可选 `visual-no-icon`
- 同步导出可选 `visual-no-icon`
- 两边输出结构一致
- 说明文档有明确描述

### 8.2 临时栏目

- 手动导出与同步导出都稳定生成两类目录
- 导入能够正确恢复普通临时栏目与特殊临时栏目

### 8.3 空白栏目

- 导出目录中能够清楚体现空白栏目两类
- 导入能够正确恢复两类空白栏目
- 旧导出结构仍可兼容导入

### 8.4 一致性

- 手动导出、同步导出、导入恢复三者目录语义一致
- 中文路径与英文路径各自内部一致

## 9. 实施顺序建议

1. 补齐手动导出 `visual-no-icon`
2. 固化临时栏目目录命名
3. 设计并落地空白栏目双目录结构
4. 补导入兼容
5. 补同步拉取兼容
6. 更新说明文档
