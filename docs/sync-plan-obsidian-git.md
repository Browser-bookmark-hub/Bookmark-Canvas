# Bookmark-Canvas Obsidian Git 主同步计划书

> 返回文档索引：[docs/README.md](./README.md)

## 1. 目标

- 以 Obsidian Git 作为主同步链路，服务 Bookmark-Canvas 的跨设备数据同步。
- 提供可控的自动同步策略，兼顾高频编辑与稳定性。
- 冲突时不静默覆盖，提供可见、可恢复的冲突处理流程。

---

## 2. 同步流程（固定）

单次“同步”流程固定为：

1. `commit`
2. `pull (merge)`
3. `push`

说明：

- 采用 merge 流程，符合 Obsidian Git 常用工作流。
- 不使用强制 rebase 作为默认路径，减少用户理解成本。

---

## 3. 触发策略

- 事件防抖（默认 800ms）
- 定时兜底（默认 180 秒）
- 手动“立即同步”

大批量操作（导入/大量移动）时延长防抖窗口（默认 5 秒）。

---

## 4. 冲突处理

默认策略：**暂停并进入冲突处理面板（人工确认）**。

面板能力：

- 列出冲突文件。
- 每个文件可选：本地优先 / 云端优先 / 保留双方副本。
- 处理后继续执行 push。

---

## 5. UI 入口（固定）

1. 设置菜单：导入/导出下方新增“同步”按钮。
2. 管理弹窗：导入/导出下方新增“同步”按钮。
3. 点击“同步”后打开二级 UI：
   - 自动同步开关
   - 保存后同步开关
   - 定时间隔
   - 冲突策略
   - 手动同步动作
   - 同步状态展示

---

## 6. 风险与边界

- 高并发改动可能引发频繁冲突，必须依赖单飞队列与防抖。
- 自动策略只能降低冲突概率，不能消除冲突。
- 需要明确告知用户：冲突处理优先“保留数据”，再做人工收敛。

---

## 7. 验收标准

- 高频编辑下自动同步稳定，不出现重复并发任务。
- 冲突出现时有明确提示与处理入口。
- 冲突处理后可继续完成同步流程。
- 导入/导出现有功能不回归。

---

## 8. 默认参数

- 事件防抖：800ms
- 批量防抖：5000ms
- 兜底定时：180s
- 队列并发：1（单飞）
- 重试退避：2s → 5s → 10s → 30s → 60s
