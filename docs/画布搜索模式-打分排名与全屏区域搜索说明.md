# 画布搜索模式、打分排名与全屏区域搜索架构说明

本文档详细记录 Bookmark-Canvas 画布搜索系统的三大搜索模式（书签模式、卡片模式、说明模式）的核心算法、打分加权矩阵、排序决胜规则，以及在**卡片全屏（Fullscreen）**、**多侧边栏 / 多标签页**环境下的隔离机制与**区域搜索（Area Search）**专有 UI 的完整设计。

---

## 一、搜索架构与评分管线总览

画布搜索（`searchCanvasAndRender`）采用多阶段处理管线：

```
用户输入 (Query)
   │
   ├─► 1. 语法检测与模式路由 (Tag / Note / Time / Permanent / Group)
   ├─► 2. 作用域判定 (全局 / 区域 Area / 全屏 Fullscreen)
   ├─► 3. 严格分词 AND 过滤 (任一 Token 无法命中则得分为 -Infinity 并剔除)
   ├─► 4. 字段基础命中打分 (Token Score: Title, Label, Note, Tags, Path, URL, Text 等)
   ├─► 5. 连续短语加权 (Phrase Bonus: 多词完整连贯匹配加分)
   ├─► 6. 语义意图与时效加权 (Intent & Recency Bonus: 笔记、标签多寡、近30天时效)
   ├─► 7. 视口全屏聚焦加权 (Scope Bonus: 当前全屏卡片内条目额外提权)
   └─► 8. 阶元分层与决胜排序 (Tier-based Sorting & Tie-breakers)
```

---

## 二、三大搜索模式打分与加权规则

### 1. 书签模式（Bookmark Mode）

面向网页书签与书签文件夹，综合考虑匹配度、用户个人注解（笔记与标签）以及时间新近度，并在展示层将相同内容（URL + Title）聚合归并。

#### 1.1 打分与加权矩阵表

| 影响维度 | 匹配对象 / 触发条件 | 分数 / 加权分值 | 说明与算法逻辑 |
| :--- | :--- | :--- | :--- |
| **基础分词得分**<br>*(按 Token 命中)* | **标题（Title）前缀匹配** | **140 分** | `itemTitle.startsWith(token)`，书签核心特征 |
| | **显式标签（Tag）匹配** | **135 分** | 显式输入 `#tag` 命中了书签标签 |
| | **显式笔记（Note）匹配** | **135 分** | 显式输入 `*note` 命中了书签笔记 |
| | **隐式/普通词命中标签** | **120 分** | 关键词未加 `#` 但包含在标签名中 |
| | **隐式/普通词命中笔记** | **115 分** | 关键词未加 `*` 但包含在笔记正文中 |
| | **标题（Title）包含匹配** | **110 分** | 标题中包含关键词文本 |
| | **路径（Path）前缀匹配** | **105 分** | 书签所在目录层级路径起始匹配 |
| | **路径（Path）包含匹配** | **95 分** *(单字 70)* | 书签所在目录层级包含关键词 |
| | **URL 链接包含匹配** | **90 分** *(单字 70)* | 链接域名或 URL 路径包含关键词 |
| | **创建时间文本包含** | **85 分** *(单字 60)* | 格式化后的时间字符串匹配 |
| **严格 AND 约束** | 存在任一 Token 均未命中 | **直接剔除** (`-Infinity`) | 用户输入多个词时，必须全部 Token 均有得分 |
| **短语连贯加权**<br>*(Tokens > 1)* | 完整短语匹配标题 (Title) | **+30 分** | 多词连续顺序完全匹配标题 |
| | 完整短语匹配笔记 (Note) | **+20 分** | 完整命中笔记文本 |
| | 完整短语匹配 URL / Path | 各 **+15 分** | 完整命中链接或所在文件夹路径 |
| **意图与辅助加权**<br>*(得分 > 0 时叠加)* | **带个人笔记（Note）** | **+20 分** | 凡是附加了用户自定义笔记的书签统一提权 |
| | **带分类标签（Tags）** | **+15 ~ +24 分** | 基础 +15 分，每额外多 1 个标签再 +3 分（最高 +24） |
| | **新近添加时效（Recency）** | **+10 分** / **+5 分** | 近 30 天内新增 +10 分；近 180 天内新增 +5 分 |
| **全屏聚焦加权**<br>*(Scope Bonus)* | 当前全屏查看的临时栏目书签 | **+620 分** | 当前全屏临时卡片内的书签置顶加分 |
| | 当前全屏查看的永久栏目书签 | **+600 分** | 当前全屏永久卡片内的书签置顶加分 |

#### 1.2 排序与同分决胜规则（Tie-breakers）

书签结果按内容唯一键（URL + Title，文件夹按 Title）聚合为组模型。组内与组间的排序由 `compareCanvasBookmarkScoredPairs` 决定：

1. **原始匹配分（rawScore）降序**：避免单纯依赖全屏加权压制高相关度的全局项；
2. **综合分（s = rawScore + scopeBonus）降序**；
3. **全屏范围优先级（Scope Priority）**；
4. **卡片规范位置优先级（Canonical Priority）**：永久主栏目 `#A` (0) > 永久副本 `#B/#C` (1) > 临时栏目 (2) > 其他 (3)；
5. **文件夹倾斜**：同分时**文件夹**排在**网页书签**之前；
6. **创建时间降序**：最新添加的书签排在前面；
7. **书签顺序（bookmarkSearchOrder）** -> **标题自然排序** -> **URL 字母序**。

### 2. 卡片模式（Card / Structure Mode）

面向画布实体结构，包含：**永久栏目卡片（#A/#B）、临时栏目卡片（A-1/A-2）、卡片组（Card Group）、锚点（Anchor）、连线（Edge）**。支持语法精确定位并强制四级阶元分层。

#### 2.1 打分与加权矩阵表

| 影响分类 | 匹配对象 / 触发场景 | 分数 / 加权分值 | 说明与规则 |
| :--- | :--- | :--- | :--- |
| **语法精确定位**<br>*(最高优先级语法)* | **槽位语法精准命中锚点** | **320 分** | 输入 `槽位1`、`slot1`、`临时槽位1` 精准命中对应槽位号 |
| | **序号/字母匹配永久卡片** | **300 分** | 输入 `#A`、`A`、`#1` 精准命中对应永久栏目/副本 |
| | **数字精准匹配手动锚点槽位** | **300 分** | 输入纯数字（如 `1`）匹配手动固定锚点槽位号 |
| | **数字精准匹配临时锚点槽位** | **280 分** | 输入纯数字匹配自动视口/临时锚点槽位号 |
| | **锚点关键词搜索** | **200 ~ 260 分** | 匹配 `锚点`、`anchor`、`手动锚点`、`临时` 等预置词汇 |
| | **临时卡片群组编号匹配** | **250 分** | 输入 `A-`、`A-1` 前缀匹配临时栏目的 Label 编号 |
| **普通分词匹配**<br>*(按 Token 命中)* | **临时卡片 Label / Title** | 完全匹配 **170~180**<br>前缀 **150~160**<br>包含 **120~130** | 匹配卡片编号（如 `A-1`）或自定义标题 |
| | **永久卡片 Label / Title** | 完全匹配 **170~250**<br>前缀 **150~180**<br>包含 **130** | 匹配永久卡片自定义标签名或标题 |
| | **卡片组（Group）Title / Label**| 完全匹配 **160** / 前缀 **140** / 包含 **115** | 匹配卡片组标题或标签 |
| | **Markdown 卡片 Title / Text** | Title 完全 **170** / 前缀 **150** / 包含 **120**<br>正文 Text 包含 **90** *(单字 60)* | 包含在普通卡片标题或正文文本 |
| | **栏目说明文本（Description）** | 包含 **70~80 分** *(单字 50)* | 包含在栏目卡片自带的备注说明中 |
| **短语连贯加权**<br>*(Tokens > 1)* | 完整短语匹配 Title / Label | 各 **+50 分** | 完整短语连续命中卡片标题或编号 |
| | 完整短语匹配 Text / Description| Text **+30 分** / Description **+25 分** | 完整命中卡片正文或栏目说明 |
| **全屏聚焦加权**<br>*(Scope Bonus)* | 当前全屏查看的永久副本卡片 | **+720 分** *(主栏目 +640)* | 当前全屏正在查看的卡片实体置顶 |
| | 当前全屏查看的临时栏目卡片 | **+700 分** | 当前临时栏目卡片实体置顶 |

#### 2.2 阶元分层与决胜规则

卡片模式在分数排序之前，由 `getCanvasSearchItemSortTier` 强制分层：

```
Tier 1: 手动固定锚点 (始终位于最前)
  └─► Tier 2: 临时/自动锚点 (紧随手动锚点之后)
        └─► Tier 3: 卡片组 (紧随锚点之后)
              └─► Tier 4: 其他栏目卡片、MD卡片与连线
```

- **同阶元内决胜规则**：
  1. **综合得分（`s`）降序**；
  2. **Tier 1（手动锚点）**：按槽位号（`slotNumber`）**升序**排列；
  3. **Tier 2（临时锚点）**：按时间戳（`timestamp`）**降序**排列；
  4. **Tier 3 / Tier 4**：按标题或标签字母序稳定排序。

### 3. 说明模式（Description Mode）

说明模式面向画布上的知识说明与图谱连线关系，严格过滤出：
1. **Markdown 卡片（`md-node`）**；
2. **关系连线说明（`edge`）**；
3. **附带了备注说明文本（`__description`）的永久或临时栏目卡片**。
*(纯书签在此模式下会被严格剔除)*

#### 3.1 打分与加权矩阵表

| 影响分类 | 匹配对象 / 触发场景 | 分数 / 加权分值 | 说明与规则 |
| :--- | :--- | :--- | :--- |
| **基础分词得分**<br>*(按 Token 命中)* | **Markdown 卡片标题前缀** | **150 分** | `itemTitle.startsWith(token)` |
| | **连线标签（Edge Label）前缀** | **140 分** | 连线上的关系说明前缀匹配 |
| | **Markdown 卡片标题包含** | **120 分** | 说明卡片标题中包含关键词 |
| | **连线标签（Edge Label）包含** | **110 分** | 连线上的关系说明包含关键词 |
| | **临时/永久栏目标题或标签** | **100 分** | 带有说明的栏目卡片标题/标签命中 |
| | **Markdown 卡片正文（Text）** | **90 分** | 便签说明卡片的 Markdown 正文匹配 |
| | **临时栏目说明文本（Desc）** | **80 分** | 临时栏目卡片备注说明匹配 |
| | **永久栏目说明文本（Desc）** | **70 分** | 永久栏目卡片备注说明匹配 |
| **严格 AND 约束** | 存在任一 Token 均未命中 | **直接剔除** (`-Infinity`) | 多词联合搜索时，任一词未命中说明内容直接过滤 |
| **短语连贯加权**<br>*(Tokens > 1)* | 完整短语匹配 Title / Label | 各 **+40 分** | 完整多词连续短语命中卡片标题或连线说明 |
| | 完整短语匹配 Text / Description| 各 **+30 分** | 完整多词连续短语命中正文或栏目说明 |
| **全屏隔离与加权** | 当前全屏查看的卡片说明/连线 | **+760 分** (MD卡片)<br>**+300/+240 分** (关联连线) | 全屏视口内的说明内容优先呈现 |
| | 非当前全屏卡片中的说明内容 | **分流至 others 列表** | 全屏下非本卡片的说明被归入“展示其他”，点击后才显示 |

## 三、卡片全屏与多侧边栏 / 多标签页的隔离机制

在实际使用中，用户可能同时打开了主标签页画布、Chrome 侧边栏（Sidepanel）或者多个浏览器窗口。

### 1. 视图分区隔离（Partitioning）
系统将画布视图状态严格隔离为两大独立分区：
- `page`：标准浏览器标签页/全页面；
- `sidepanel`：Chrome 原生侧边栏面板。

全屏状态通过 `canvasViewPartitionKey` 分别存储在独立的 Storage Key 下：
```text
canvas:view:v1:fullscreen:page:canvas-node-maximized-v1
canvas:view:v1:fullscreen:sidepanel:canvas-node-maximized-v1
```

### 2. 搜索范围的本地 DOM 判定原则
在 `search.js` 中，全屏范围的检测依据为：
```javascript
function getCanvasFullscreenSearchScope() {
    try {
        const maximized = document.querySelector('.canvas-node-maximized');
        return getCanvasFullscreenScopeFromElement(maximized);
    } catch (_) {
        return null;
    }
}
```
**关键机制**：
- `document.querySelector('.canvas-node-maximized')` 仅检索**当前页面/侧边栏的自身本地 DOM 树**。
- **结论**：若在一个侧边栏中将某张卡片最大化全屏，**其他侧边栏、其他标签页不会被自动聚焦到该卡片上**。其他页面的 DOM 中不存在 `.canvas-node-maximized`，因此其搜索仍然是**纯正的全局画布搜索**。
- **跨端手动同步**：只有当用户在卡片全屏工具栏中显式点击“将全屏同步到 标签页 + 侧边栏”（触发 `__syncFullscreenAcrossAllPartitions()`）时，才会通过 `CANVAS_VIEW_SYNC_SIGNAL_KEY` 广播信号让其他窗口也同步进入该卡片的全屏。

## 四、专门的“区域搜索（Area Search）”专有 UI 与交互

系统设计了完整的专属“区域搜索”体系，无需担心被锁定或无法跳出的问题。

### 1. 搜索框内置“区域（Area）”胶囊指示器
在搜索输入框内部（`.search-input-wrapper`）配置了原生的指示器组件：
```html
<div class="search-input-wrapper">
    <input type="text" id="searchInput" name="searchInput" />
    <div id="searchAreaIndicator" class="search-area-indicator" style="display: none;">
        <span class="search-area-indicator-label" data-i18n-key="searchAreaLabel">区域</span>
        <button id="searchAreaExitBtn" class="search-area-exit-btn"
            data-i18n-title="searchAreaExitTitle" title="退出区域搜索" aria-label="退出区域搜索" type="button">
            <i class="fas fa-times"></i>
        </button>
    </div>
</div>
```
- **自动显隐**：当卡片全屏、或通过工具栏触发区域搜索时，输入框右侧会自动亮起蓝色 **`区域`**（英文环境下为 **`Area`**）胶囊徽标。
- **一键退出（`searchAreaExitBtn`）**：用户随时可以点击胶囊上的 `×` 按钮调用 `exitAreaSearch()`，即使卡片依然保持全屏，搜索也能立即**解除锁定并切回全局画布搜索**。

### 2. 画布中的主动触发入口（Trigger Entrypoints）
除全屏自动挂钩外，系统在画布多处均提供了显式触发区域搜索的交互：
1. **卡片/栏目工具栏**：临时栏目与永久栏目卡片顶部工具栏内置搜索按钮，点击即限定搜索本栏目；
2. **卡片组工具栏（`card_group_toolbar.js`）**：卡片组顶部带有“搜索此组”按钮，一键搜索属于该组的所有卡片与书签；
3. **套索与框选浮动条（`lasso_and_temp_group.js`）**：在画布上用鼠标框选多张卡片后，浮动操作条支持对当前选区发起区域搜索；
4. **右键上下文菜单（Context Menu）**：右键点击任何栏目或卡片，菜单中均提供“搜索此栏目/选区”指令。

### 3. 搜索模式在全屏区域下的智能适配
- **书签模式**：严格将候选集限定在当前全屏卡片（临时卡片对应 ID 或永久主栏目/副本）；
- **说明模式**：当前全屏卡片内的说明直接展示；非当前卡片的匹配项保留在底部的“展示其他”按钮中，兼顾聚焦与全局探索；
- **卡片/结构模式**：**全屏下自动豁免区域限制**（`if (searchUiState.activeMode === 'structure') return null;`），因为卡片模式的核心职责在于定位与切换卡片实体，避免用户在全屏时无法搜索并切换至其他卡片或锚点。
