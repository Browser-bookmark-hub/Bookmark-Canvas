# 画布富文本：格式继承、退出与工具窗说明交互计划

状态：**采用 `?` 左对齐快捷键/语法说明＋片段末尾 `→` 退出，不新增“普通输入”按钮**。无选区、位于行内格式片段末尾时，按一次普通 `→` 恢复普通输入，不插入字符、不改已有文字；再次按键恢复正常导航。`Ctrl+\` / `Cmd+\` 保留为任意光标处的统一退出快捷键。工作区已实现，待真实输入法及导航人测；重入边界自动重置仍未实施。

基线：`3845995`。适用对象：空白栏目、临时栏目说明、永久栏目及副本备注；包含独立页面、侧边栏和卡片全屏。

## 1. 本次要解决什么

用户说的“粘合”，指的是输入完高亮、加粗等内容后，后续文字仍不断继承格式，或者退出编辑再进入，追加内容又自动带上原格式。

需要区分三个动作：

1. **停止格式输入**：已有文字不变，接下来输入恢复普通。
2. **清除选区格式**：主动修改已选中文字的格式。
3. **退出编辑/收起工具窗**：改变界面状态，不等于清除格式。

这三件事不能混用一个含糊的操作。本轮实现第 1 项的统一快捷键、片段末尾方向键出口和说明；重入边界行为另行确认。

## 2. 现状与讨论结论

### 2.1 已有能力

- 工具按钮和格式快捷键采用行内单选：加粗、斜体、下划线、高亮、删除线、行内代码、字体颜色，后选的替换前选的。
- 格式按钮显示编辑器实际状态，不只是记录上一次点击。
- 无选区时再次点击已启用的格式，可停止该格式的后续输入。
- 手写 Markdown、粘贴和导入可保留组合；不批量清洗历史数据。
- 原有 Markdown 自动转换和立即 Backspace 回退仍由 Tiptap 处理。
- 关闭按钮左侧已有 `?`“编辑说明”入口，使用左对齐紧凑列表，保留各格式快捷键并补充对应 Markdown/HTML 语法和退出方式，不使用表格。
- `Ctrl+\` / `Cmd+\` 停止下一输入的全部行内格式及链接延续；不修改正文、块结构或选区，不新增内容撤销步骤。
- 格式片段末尾按一次普通 `→` 停止后续格式；覆盖七类行内样式及链接，不插空格、不改正文，下一次方向键恢复导航。

### 2.4 主流做法核实（2026-11-13）

以下为已直接核实的官方文档，不代表用户调研或所有产品都一致：

| 资料 | 实际约定 | 对本项目的含义 |
| --- | --- | --- |
| [Tiptap Bold](https://tiptap.dev/docs/editor/extensions/marks/bold) | `toggleBold` / Ctrl、Cmd+B 是开关 | 再点当前按钮或再次按格式快捷键，是已有基础路线 |
| [Google Docs 快捷键](https://support.google.com/docs/answer/179738?hl=en) | 清除文字格式：Ctrl+\\ / Cmd+\\；Windows 另列 Ctrl+Space | 统一恢复入口有现成参照，但“清除已有格式”不等同于本计划只停止后续输入，不能直接照搬选区语义 |
| [Word 快捷键](https://support.microsoft.com/en-us/office/keyboard-shortcuts-in-word-95ef89dd-7142-4b50-afb2-f762f663ceb2) | Ctrl+Space 移除手动字符格式；Esc 取消命令；同页也列出中文输入法 Ctrl+Space | 不用 Esc 代替格式开关，也不直接占用中文输入法按键 |
| [TinyMCE 快捷键](https://www.tiny.cloud/docs/tinymce/latest/keyboard-shortcuts/) | Esc 关菜单/对话框/通知，或返回正文焦点 | Esc 常用于关闭界面层级，不是通用的解除行内格式命令 |
| [Notion 快捷键](https://www.notion.com/help/keyboard-shortcuts) | Esc 选择/取消选择块，关闭命令菜单 | Notion 的 Esc 也不是统一清除加粗/高亮 |
| [CKEditor 行内代码](https://ckeditor.com/docs/ckeditor5/latest/features/basic-styles.html#typing-around-inline-code)、[链接边界](https://ckeditor.com/docs/ckeditor5/latest/features/link.html#typing-around-links) | 光标在边界时，向外按一次方向键，可在片段外输入 | 本轮借鉴边界退出；扩展到其他行内样式是本产品选择，不是所有编辑器的共同规则 |
| [Apple 双空格替换](https://support.apple.com/guide/mac-help/replace-text-punctuation-documents-mac-mh35735/mac)、[CommonMark 硬换行](https://spec.commonmark.org/0.31.2/#hard-line-breaks) | 系统可将双空格换成句号＋空格；Markdown 行尾两个空格＋换行可表示硬换行 | 双空格存在内容/系统语义，不宜作为默认隐藏退出手势 |

结论：**在本轮核实的官方资料中，没有发现 Esc 或双空格是通用的“解除格式粘连”约定。** 本轮保留按钮/格式快捷键开关，采用 `Ctrl+\` / `Cmd+\` 统一停止后续格式；这里只借用 Google Docs 的键位，不照搬清除选区格式的语义。

“重入时内部继承、边界普通”仍是画布短文本的产品提案，不是上述资料证明的通用规则。当前采用 `?` 入口、统一退出快捷键和片段末尾 `→`，不新增按钮。

## 3. 编辑过程中，到底用什么退出

### 3.1 推荐选择

| 候选方式 | 建议 | 理由 |
| --- | --- | --- |
| 再点当前格式按钮 | 保留，作为常用出口 | 开/关行为一致，现有用户容易理解 |
| “普通输入”按钮 | **本轮不新增** | 用户选择快捷键方案，避免继续增加工具栏按钮 |
| 格式快捷键 | 保留；**新增 Ctrl+\ / Cmd+\ 统一退出** | 不必判断是哪一种行内格式，`?` 提供明确提示 |
| 方向键 | **片段末尾按一次普通 → 退出格式** | 不插字符，不影响内部移动、扩选和跳词 |
| 双空格 | **不作为默认退出指令** | 空格是有效数据，还涉及 Markdown 行尾硬换行和输入法行为 |
| Esc | **不用于停止格式输入** | 已承担候选取消、弹层关闭和退出/取消编辑等职责 |
| Enter | 本轮不新增强制清除规则 | 保留段落、列表、引用和代码块原有逻辑，避免额外隐式行为 |

### 3.2 编辑期间的行为表

| 用户操作 | 预期行为 |
| --- | --- |
| 无选区，点击 H 后连续输入 | 持续高亮，H 持续亮 |
| 无选区，再次点击 H | 停止高亮；原高亮文字保留，后续普通输入 |
| 无选区，按 Ctrl+\ / Cmd+\ | 停止全部待输入行内格式和链接延续；已有文字不变 |
| 无选区，在格式片段末尾按 → | 停止下一输入格式，不插字符；再按恢复导航 |
| 有非空选区，按 Ctrl+\ / Cmd+\ | 本轮不处理，不清除选区格式、不移动选区 |
| 无选区，高亮状态改点 B | 之后改为加粗；之前的高亮不动 |
| 有选区，点击 B/H 等工具 | 只替换选区的行内格式，前后文字不动 |
| 光标进入普通文字内部 | 后续按普通文字输入，不携带别处的手动格式锁定 |
| 光标进入高亮文字内部 | 继承当前位置的高亮，便于补字 |
| 连续输入空格、标点 | 按当前实际格式输入；不吞字，不自动猜测退出 |
| 关闭工具窗 | 仅收起工具窗，不顺带停止格式输入 |
| 点击“编辑说明” | 只查看说明，不改变格式或结束编辑 |

已关闭的格式必须保持关闭：不能因下一个字符紧邻原格式文字，就自动重新继承回来。

### 3.3 “普通输入”命令的准确含义（仅快捷键）

命令：`setPlainTyping`；快捷键：**Ctrl+\ / Cmd+\**。本轮不新增按钮。

- **无选区**：重置下一输入的行内格式，不修改文档中的已有文字。
- 退出待输入的加粗、斜体、下划线、高亮、删除线、行内代码和字体颜色。
- 若下一输入将延续链接，也停止后续链接输入，但不删除已有链接或 URL。
- 保留标题、列表、引用、段落对齐、卡片字号等结构/整体样式；“普通”不是把整段改成默认段落。
- 保留焦点和光标位置，相关格式按钮立即熄灭。
- **有非空选区时不处理**，不暗中清空选区格式，也不擅自把光标移到选区末尾；节点选区和只读编辑器也不处理。箭头说明明确“片段末尾”。
- “清除选区格式”如需新增，单独设计、单独命名，不包含在本期。

字体颜色菜单中的“默认颜色”只清除颜色，不代替这个统一出口。

### 3.4 快捷键实现与冲突范围

- 保留已有 Ctrl/Cmd+B、I、U 等格式切换快捷键。
- 采用 **Ctrl+\ / Cmd+\**。代码检索未发现固定键位冲突，扩展 manifest 未注册该组合；已有自定义锚点快捷键在文本编辑时跳过。操作系统/浏览器扩展可能另行占用，真实浏览器和键盘布局仍需人测。
- 不占用 Ctrl+Space，避免与中文输入法切换冲突；不占用 Esc。
- 只在编辑器上下文内处理，不劫持整张画布或浏览器的全局快捷键。
- 输入法组合期间和带额外 Alt/Shift/双修饰键的组合不处理；使用 ProseMirror 平台键位识别与 keyCode 回退，不按物理键位置硬抢其他布局字符。

## 4. 退出编辑后重新进入

### 4.1 待确认的产品提案（本轮未实现）

> **内部修改继承原格式，边界追加默认普通；上一次编辑会话的手动开启状态不跨会话锁定。**

| 重新进入的位置/方式 | 下一输入格式 |
| --- | --- |
| 点在高亮、加粗等片段内部 | 继承实际落点格式 |
| 点在该片段末尾，准备追加文字 | 默认普通行内输入 |
| 点在普通文字内部或末尾 | 普通输入 |
| 点在两个不同格式片段交界处 | 默认普通，不猜左边还是右边 |
| 非坐标入口，明确将光标放到文末 | 若文末为格式边界，默认普通 |
| 重新进入后主动点 H/B 等工具 | 本次明确选择优先，进入对应输入状态 |

格式片段起点也建议按“边界插入默认普通”处理；严格位于内部时才自动继承。具体边界应按文档格式区间判断，不是屏幕像素或“同一行”判断。

### 4.2 示例

原文：`[高亮文字]`，`|` 表示光标。

```text
重新进入，在末尾追加：
[高亮文字]|补充说明
结果：只有原文高亮，“补充说明”普通。

重新进入，在内部修改：
[高亮|文字]
结果：插入的字继续高亮。
```

### 4.3 不应误触发重置的情况

- 点击工具栏、颜色弹层、说明弹层后返回编辑器：仍属于同一次编辑，不算重新进入。
- 卡片全屏切换、滚动、窗口焦点切换：不能单凭 focus/blur 就认定新会话。
- 用户已主动选择工具，再异步聚焦：初始化不得把刚选的格式清掉。
- 同次编辑中点击/移动到其他位置：按落点和当前输入状态处理，不套用“每次 focus 都清空”。

## 5. 方向键边界退出：当前实现

不是“按右键就随时取消格式”，而是只在适用的格式边界提供额外出口。

1. 无选区，光标紧邻已有格式文字的末尾，且下一输入仍会继承结束于此的行内格式（加粗、斜体、下划线、高亮、删除线、行内代码、颜色或链接）。通过文档位置和完整 mark 属性判断，不按屏幕像素或折行判断。
2. 按一次普通 `→`，清空下一输入的行内格式，恢复普通；片段内容和链接 URL 不变。某个格式结束但另一格式仍延续时，也允许明确退出为普通。
3. 光标可以仍处在同一文档位置，但对应格式指示应明确关闭，下一输入在片段外。
4. 再按方向键恢复正常移动；已有普通输入状态时，不反复拦截制造“走不动”。

约束：

- 不插入空格、零宽字符或伪造空节点。
- 不拦截 Shift+方向键扩选、Ctrl/Option/Meta 的跳词/导航操作。
- 不处理输入法候选/组合期间的按键；双向/RTL 文字段落及显式 RTL 编辑上下文保持原生导航，不以物理方向猜测逻辑方向。此类场景仍可用统一快捷键。
- 代码块里的方向键保持导航用途，不当成退出行内代码。
- `canvas-starter-kit.js` 仅关闭链接/行内代码原生 `exitable` 的插空格退出逻辑，保留其 schema、解析和命令；统一由共享边界命令处理。不把全部格式设成 `exitable` 或全局 `inclusive: false`。
- 一旦启用，说明应提供提示；统一退出快捷键仍可使用。

不改变标记的继承模型。普通文字、格式内部、刚开启但尚未输入的样式、已显式普通输入的位置不拦截；已有字符数量、节点结构和撤销步骤不变。

## 6. 关闭按钮左侧增加“编辑说明”

当前进度：已独立接入两类工具窗，覆盖空白栏目、临时说明、永久备注及副本。按用户反馈，删除格式作用范围、行内单选、重复点击按钮、默认颜色、组合内容和关闭工具窗职责等通用说明，改为只讲格式粘连的实用处理办法。新增自动化检查覆盖选区/待输入标记不变、说明 Esc 不穿透、外部点击保存和生命周期清理；真实侧边栏布局、输入法和触控仍待人测。

### 6.1 位置与布局

**采纳：说明入口紧挨关闭按钮左侧。** 图标用圆圈问号 `?`，悬停提示和无障碍名称为“编辑说明”。

推荐尾部顺序：

```text
…… 格式工具 …… | ? | ×
                  说明  关闭工具窗
```

- `?` 只说明，不能点击后清除格式。
- `×` 只收起工具窗，不能被误认为“取消高亮/恢复普通”。
- 空白栏目与备注共用说明内容；深浅主题、侧边栏、全屏的文案一致。
- 侧边栏空间不足时优先使用图标和 tooltip；不要为了增加说明按钮把关闭按钮挤出可视区域。
- 只说明已实现的快捷键、语法和片段末尾方向键出口，不承诺重入边界自动重置。

### 6.2 当前说明文案

标题：**编辑说明**

使用左对齐紧凑列表，无表格边框/表头：操作名称、快捷键和右侧语法分区共用固定对齐起点，语法统一左对齐，窄屏时样例可自然换行。恢复普通输入的方向键放在右侧语法分区，与其他语法起点对齐。

- 加粗：`Ctrl/Cmd+B`，`**文字**`
- 斜体：`Ctrl/Cmd+I`，`*文字*`
- 下划线：`Ctrl/Cmd+U`，`<u>文字</u>`
- 高亮：`Ctrl/Cmd+Shift+H`，`==文字==`
- 行内代码：`Ctrl/Cmd+E`，反引号包裹文字。
- **恢复普通输入**：`Ctrl/Cmd+\`；右侧语法分区显示 `→`（片段末尾）。

最后一项操作名称仍用黄色文字，不恢复平台小字、Esc/双空格提醒或其他通用说明。语法样例以字面文本显示，HTML 不执行；不承诺所有源码都在逐字输入时即时转换。现有 UI 宽度内紧凑排布，不增加新工具按钮。

### 6.3 弹层交互

- 点击/键盘激活 `?` 打开非模态说明弹层，靠近按钮定位，并根据视口上下翻转、水平钳制。
- 不要只有 hover 才能阅读；鼠标、触控和键盘用户都能打开。
- 打开时保留编辑选区和待输入格式；帮助不触发保存、取消或销毁编辑器。
- 工具栏之外的说明弹层要纳入“允许交互区域”，避免备注失焦误退出。
- 点 `?` 再次关闭，或点击外部关闭；点击画布空白时，说明关闭且原有编辑失焦保存仍应正常执行。
- 说明弹层内按 Esc **只关闭说明并消费这次事件**，不能冒泡导致临时备注取消整次编辑。
- 输入法组合期间不抢占 Esc；尚有候选时让输入法优先。
- 关闭后恢复原来的编辑焦点/选区，或按键盘导航返回说明按钮，不擅自移到文末。
- `?` 使用 `aria-expanded`/`aria-controls`；内容可读、焦点可到达，说明写清快捷键及“不选中文字时”的条件。
- 每个编辑器有明确 owner；切卡、销毁、导入、虚拟化时清理弹层和监听器。

## 7. Esc 的现有差异与范围限制

当前实际行为并不统一：

- 空白栏目：普通 Esc 会退出编辑并保存当前内容。
- 临时说明：普通 Esc 会取消本轮备注编辑。
- 永久备注：普通 Esc 在没有相关弹层时提交退出，有弹层时受弹层处理影响。

因此一期**不把 Esc 改成停止格式，也不顺带统一所有编辑取消语义**。只保证新说明弹层的 Esc 不穿透。后续若统一 Esc，另开需求并覆盖现有取消/提交流程。

## 8. 实施思路与文件边界

### 8.1 编辑器状态

- 用 ProseMirror 的待输入标记控制停止格式，而不是改写正文 DOM。
- 明确区分“未显式设置、可从落点继承”与“显式普通输入”；不能使用一个会立即重新继承旧格式的空值糊弄退出。
- 重新进入时先确定真实文档落点，再判断格式区间边界、设定输入状态，最后同步工具栏。
- 一期的重入/普通输入操作不应改变 Markdown、HTML、节点类型或格式文字数量，不额外产生内容脏标记/持久化写入。
- 不用 DOM 扫整行，不为显示说明做全篇解析；换行折行与格式边界是两回事。
- 原生 input rule 的 Backspace 回退、撤销重做和用户明确组合格式保留。

### 8.2 主要文件

| 文件 | 计划职责 |
| --- | --- |
| `tools/build-tiptap-bundle/src/`、`entry.js` | 统一停止输入格式和片段末尾方向键命令，关闭代码/链接原生插空格退出；不新增重入自动重置 |
| `Bookmark-Canvas-main/history_html/bookmark_canvas_module.js` | 两类工具窗的按钮入口、编辑会话接线、说明弹层生命周期 |

## 9. 分阶段交付

### 阶段 A：确认交互范围

- 已确认统一退出使用 Ctrl+\ / Cmd+\，不新增普通输入按钮；`?` 紧邻关闭按钮左侧。
- 有选区时不清格式，清除选区格式不混进来。
- 补充片段末尾普通 `→` 的无字符退出；重入边界规则延后，双空格/Esc/Enter 本轮不新增退出规则。

### 阶段 B：第一期实现

1. 实现不改正文的停止输入命令，覆盖七类行内样式及后续链接延续。
2. 在共享引擎接入 Ctrl+\ / Cmd+\，覆盖空白栏目/临时说明/永久备注/副本，不加全局监听。
3. 增加片段末尾 `→` 的无字符退出，移除链接/代码原生插空格退出；格式内部、修饰键和输入法保持导航，不新增 focus 重置。
4. `?` 用左对齐列表保留各格式快捷键并补语法样例，黄色强调退出操作，处理说明的 Esc 与失焦边界。
5. 自动化、人测、更新 bundle 和文档后交付。

### 阶段 C：人测与后续候选

验收方向键无字符退出是否可理解、是否干扰实际导航；输入法、混合文字和真实鼠标落点需手测。重入边界默认普通仍单独确认。

## 11. 依据与取舍

- [SAP Fiori 富文本交互规范](https://www.sap.com/design-system/fiori-design-web/v1-142/ui-elements/rich-text-editor/usage)：格式切换与光标落点的关系，帮助确定普通富文本的基本预期。
- [Quill format API](https://quilljs.com/docs/api#format)：区分选区格式与下一输入的格式。
- [ProseMirror storedMarks](https://prosemirror.net/docs/ref/#state.EditorState.storedMarks)：实现待输入状态，而不是在正文里插辅助字符。
- [CKEditor 内联代码边界输入](https://ckeditor.com/docs/ckeditor5/latest/features/basic-styles.html#typing-around-inline-code)：方向键边界退出可作为特定格式的辅助，不是全部工具的强制学习入口。
- [CKEditor Remove formatting](https://ckeditor.com/docs/ckeditor5/latest/features/remove-format.html)：清除样式不等于清除块结构或链接语义。
- [CommonMark 硬换行](https://spec.commonmark.org/0.31.2/#hard-line-breaks)：双空格可能是内容/语法，不适合作为默认退出控制字符。

这些是设计依据，不是“所有富文本编辑器都采用本方案”的证明。重新进入边界默认普通，是针对画布短文本/备注提出的产品选择，应以真实用户测试验收。
