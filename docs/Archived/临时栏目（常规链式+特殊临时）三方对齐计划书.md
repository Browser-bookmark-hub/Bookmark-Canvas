# 临时栏目（常规链式 + 特殊临时）三方对齐计划书

更新时间：2026-03-30  
阶段：测试阶段（未上线）  
策略：只收口临时栏目，不做永久栏目结构重构。

---

## 1. 目标

本计划只做一件事：  
让**临时栏目**在三条链路上保持同一协议与同一顺序语义。

三条链路定义：

1. 本地存储：`bcs:section:*`  
2. 导出 JSON（手动导出）：`临时栏目/常规链式/*.json`、`临时栏目/特殊临时栏目/*.json`  
3. 同步 JSON（云端推送/拉取）：与导出同协议文件

---

## 2. 范围

包含：

1. 常规链式临时栏目（含从永久栏目分裂后继续分裂链）  
2. 特殊临时栏目（`source` 标识，如 `browser-drop/search-result/batch/...`）  
3. 临时栏目说明（`descriptionMd`）、来源（`originPermanent`）、序号（`label/sequenceNumber`）

不包含：

1. 永久栏目动态字段（`id/parentId/index/dateAdded`）对齐  
2. 通用浏览器 HTML 导入格式改造  
3. 空白栏目与 `.canvas` 结构改造（已在其他计划内）

---

## 3. 锁定原则（必须遵守）

1. 临时栏目继续使用当前协议，不强行改成 Chrome API 原生字段模型。  
2. 父子关系继续以 `children` 嵌套表达，不新增 `parentId/index` 作为协议必填字段。  
3. 两类临时栏目统一协议外壳：`sectionType: "temporary"`；差异由 `tempKind/source` 表达。  
4. 三端都复用同一“协议构建 + 解析 + 比较”函数，禁止各自拼装。  
5. 顺序语义必须稳定：  
   - 节点数组顺序稳定  
   - 文件集合顺序稳定  
   - key 顺序可控（避免“看起来不同但语义相同”的噪音）

---

## 4. 现状与问题

1. 临时栏目语义已基本对齐，但不同链路存在 key 输出顺序差异。  
2. 人工对比时容易把“对象字段顺序差异”误判为“节点顺序差异”。  
3. 常规链式与特殊临时虽然都进入临时协议，但回归报告未单独分组展示，定位成本高。

---

## 5. 改造方案（小改、三方同步）

### 5.1 协议层收口

1. 固定临时栏目协议字段输出顺序（section 级 + item 级）。  
2. `__buildTempSectionJsonProtocol` 作为导出/同步唯一构建入口。  
3. `__normalizeTempSectionProtocolObject` 作为导入/同步写回唯一解析入口。

### 5.2 三方链路统一

1. 本地 BCS 落盘：按协议对象落盘，不走额外变体。  
2. 手动导出 JSON：直接使用同一协议对象输出。  
3. 云端同步 JSON：推送与拉取均复用同一协议对象。

### 5.3 顺序与比较稳定

1. 节点顺序以 `items/children` 数组原顺序为准，不做隐式重排。  
2. dirty/hash 比较统一走同一 canonical 视图（避免假差异）。  
3. 对比脚本新增分组结果：`regular` 与 `special` 分开统计与断言。

---

## 6. 验收标准

一次完整回归需同时满足：

1. `temporaryProtocolsMatch === true`。  
2. 常规链式与特殊临时分别满足：  
   - 数量一致  
   - `id` 集合一致  
   - 预序遍历顺序（preorder）一致  
3. 同一数据执行“本地 → 云端 → 本地”后，不产生额外临时栏目假差异。  
4. 手动导出与云端同步文件在临时栏目协议对象上稳定一致。

---

## 7. 执行清单

1. 梳理并锁定临时栏目协议字段顺序（section/item）。  
2. 清理导出与同步链路中的重复构建分支，统一调用协议构建器。  
3. 清理导入与同步回灌链路中的重复解析分支，统一调用协议解析器。  
4. 更新对比脚本：增加常规链式/特殊临时分组断言与顺序断言。  
5. 跑三端样本对比并产出报告文件路径。  
6. 回归分裂链、拖拽、跨栏移动、特殊临时创建等关键操作。

---

## 8. 风险与回退

风险：

1. 仅调整序列化顺序可能影响旧 dirty 记录命中率（一次性重建后应恢复稳定）。  
2. 统一解析入口若漏掉分支，可能影响个别导入来源。

回退策略：

1. 保留变更前函数签名与调用点注释，出现异常可快速回切。  
2. 以脚本报告为守门条件，不满足即不推进下一步。
