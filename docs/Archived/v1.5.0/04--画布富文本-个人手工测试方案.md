# 画布富文本：个人手工测试方案

适用范围：基于 `4a7210e` 的 Tiptap 迁移修复工作区，重点验收数据保存、格式往返和生命周期。本方案是待执行清单，不代表已经通过完整手工验收。

## 1. 一个人怎么安排

| 场景 | 建议耗时 | 执行范围 |
| --- | --- | --- |
| 每次改完后的快速自测 | 15～20 分钟，不含首次准备 | 第 4 节全部项目；优先临时备注，再检查空白卡和永久备注 |
| 准备发版 | 60～90 分钟，性能测试另留时间 | 第 5 节全部必测用例；主用浏览器的页面与侧边栏都测 |
| 改过编辑器、Schema 或存储 | 额外 20～30 分钟 | 再做导出/导入、多视图和虚拟化测试 |

**最重要的判据：不仅当场显示正确，退出编辑、刷新和重新打开后也要正确。**

建议逐条打勾，不要同时测多个功能。发现丢字、勾错任务或内容复活时，先记录复现步骤，不要继续在同一份数据上叠加操作。

## 2. 测试前准备：不要拿日常数据直接测

1. 先通过插件的导出功能备份日常画布，保留原始导出包，不覆盖它。
2. 推荐新建一个**专用浏览器 Profile**，不要开启账号同步，不连接日常 GitHub 同步目标。
3. 在 Chrome 的 `chrome://extensions` 或 Edge 的 `edge://extensions` 开启开发者模式，加载仓库中的 `Bookmark-Canvas-main/` 文件夹。
4. 若之前加载过此开发版，点击扩展管理页的“重新加载”，再关闭旧画布页面/侧边栏，重新打开。仅刷新网页不一定能替换已加载的编辑器脚本。
5. 创建或准备下面四种测试对象，标题带 `QA-`，方便识别：

   | 编号 | 对象 | 示例名称 |
   | --- | --- | --- |
   | A | 空白栏目/空白文字卡 | `QA-A-空白卡` |
   | T | 临时栏目的备注 | `QA-T-临时备注` |
   | P | 永久主栏目的备注 | 专用 Profile 中的永久栏目备注 |
   | C | 永久栏目副本的备注 | `QA-C-永久副本` |

6. 记录浏览器版本、系统、输入法；先用浅色、正常卡片模式和正常缩放测试，之后再切深色/全屏。
7. 可选：打开当前扩展页面的开发者工具 Console，开启 Preserve log，保留新增错误。侧边栏要检查侧边栏自己的上下文，不是普通网页的 Console。

### 可选：先跑自动化检查

在仓库根目录执行：

```sh
cd tools/build-tiptap-bundle
npm ci
npm test
npm run build
```

自动化通过后再重新加载扩展。测试运行器会报告实际用例数；自动化不替代下面的输入法、鼠标与刷新测试。

## 3. 测试数据：直接导入，也要手输

### 3.1 现成样例

样例文件夹：[`fixtures/tiptap-manual-test/`](fixtures/tiptap-manual-test/)。

在**专用测试 Profile** 中打开插件的导入界面，选择“画布快照 → 文件夹”，选这个文件夹；优先追加导入。它包含 6 张文字卡，不含书签树或真实用户数据。不要把 `.canvas` 文件误选到“导入 JSON 书签”入口。

| 卡片标题 | 用途 |
| --- | --- |
| QA-实体与代码 | `&copy;`、`<span>` 等字面文本、代码中的实体和重复标题标记 |
| QA-待办定位 | 引用任务、嵌套任务、普通任务、代码中的假任务 |
| QA-表格 | 单元格竖线、行内代码、加粗、多段落与合并单元格 |
| QA-折叠与旧格式 | `details/summary`、嵌套、颜色、对齐和富文本 |
| QA-链接与混合待办 | 裸 URL、Markdown 链接、HTML 待办与 Markdown 待办 |
| QA-原生文字节点 | 通过非 `md-node-` ID 导入的原生文字节点 |

这组样例只负责空白卡/原生文字节点。T/P/C 的备注仍需单独测试。需要复用复杂样例时，可从测试卡复制内容，或从 `.canvas` 文件的相应 `text` 字段取原始 Markdown；不要把整份 JSON 粘进备注。

### 3.2 必须作为字面正文输入的一行

下面这行至少**手动输入一次**。也可以先放到记事本/纯文本编辑器，再用“粘贴为纯文本”（通常 Windows 为 Ctrl+Shift+V、macOS 为 Cmd+Shift+V；以浏览器实际行为为准）放进插件：

```text
Literal &copy; and <span> and &lt;tag&gt; and A & B
```

预期：正文保持以上**字面字符**，不能出现 `©`，不能丢掉 `<span>`，也不能每刷新一次就改变。

注意：**普通粘贴也可能按 Markdown 解析**，不是从记事本复制就一定绕过解析器。作为 Markdown 源码导入或普通粘贴时，实体会按 Markdown 规则解释；样例卡已做所需转义。不能把“手输字面正文”和“导入/粘贴 Markdown 源码”的预期混为一谈。

## 4. 快速自测：先做这 8 项

通用保存动作：完成输入法上屏 → 点击画布空白处 → 等待约 2 秒 → 刷新/重新打开画布。这里的等待是普通持久化检查，不代替第 5 节的离屏卸载等待。

- [ ] **Q1 临时备注保存**：T 输入 `本次测试-日期时间`，点外部，刷新后还在；工具栏收起，再双击能继续编辑。
- [ ] **Q2 工具栏后退出**：T 选中文字 → 加粗/改色 → 点击画布空白处。既保留格式，也正常退出保存。
- [ ] **Q3 文本不变字**：A/T 手输第 3.2 节的一行（或明确粘贴为纯文本），保存后连续刷新 3 次，字符逐字一致。
- [ ] **Q4 表格不串列**：打开“QA-表格”，在第一格补字，保存刷新后，`x | y` 仍在第一格，第二格的 `z` 没丢。
- [ ] **Q5 待办不勾错**：在“QA-待办定位”的观察态勾选引用任务，刷新后只有该任务变化，后面的普通任务没变。
- [ ] **Q6 折叠块不丢**：打开“QA-折叠与旧格式”进入编辑，不改字就退出；再改一处正文后退出。两次刷新后折叠结构和内部格式都保留。
- [ ] **Q7 清空/删除不复活**：清空一条 T 备注，再删除一张专用测试卡，刷新后备注仍空、卡片仍不存在。
- [ ] **Q8 四类对象能编辑**：A/T/P/C 各输入一段中文并加粗，点外部保存，刷新后都保留。

任何一项失败，先不要用这版覆盖日常数据。按第 8 节记下来即可。

## 5. 发布前完整用例

“刷新”均指插件的画布页面/侧边栏，不是扩展管理页。普通用例测完后点击外部并等约 2 秒；强制关闭浏览器进程不属于普通保存承诺。

### T01 进入、失焦、切换、再次编辑【必测；A/T/P/C】

1. 双击进入编辑，输入唯一标记，如 `QA-T01-1430`。
2. 分别试：点画布空白、点另一张卡、点另一条备注。每种操作使用新的标记。
3. 回来再次进入编辑，补字后保存；最后刷新并重新打开。

**通过标准：**内容保留；退出后不残留编辑边框/工具栏；再次编辑不锁死；不意外创建空卡或移动卡片。备注之间不要串数据。

### T02 工具栏、颜色与焦点【必测；A/T/P，C 抽查】

1. 刷新后让 A 处于仅选中、未编辑的状态，首次点击格式按钮，应一次打开工具窗，再点一次关闭；退出编辑后重复，仍不需要连点两次。
2. A/T/P/C 在普通模式双击进入编辑时，格式工具窗自动打开；关闭后可单击重新打开。全屏不新增自动弹窗，维持原有策略。
3. 输入 `前面 普通 中间加粗 后面`，选中“中间加粗”，依次试加粗、斜体、下划线、高亮、删除线、行内代码和改色。每次只保留最后选的行内格式，其他格式边框熄灭；前后未选文字不变。
4. 打开自定义颜色输入框，改值；再试标题、列表和对齐菜单；点击外部，保存刷新。
5. 无选区时点 B / H 等格式按钮，鼠标移开后边框应保持；再点一次边框消失。尚未输入文字时也应立即变化。
6. 通过快捷键切换格式、对选区应用格式后撤销/重做，按钮状态应跟随。菜单关闭后，已应用的标题/列表/颜色状态不应跟着清空。
7. 手输尚未闭合的 `==内容`，H 不提前亮；补齐 `==` 后内容高亮，但下一输入为普通格式，H 应灭；光标移回高亮内部则 H 亮。

8. 保持选区不变，加粗→高亮→改色；分别整段复制、局部复制到另一条备注/卡片，再保存刷新，只有最后的格式保留、文字不缺失。切换格式后撤销一次应恢复上一个格式，重做恢复新的。
9. 无选区时输入加粗文字，切高亮再输入：前面的加粗文字不应被改，只有后续输入用高亮。点高亮关闭后继续输入，应为普通文字，不恢复先前的加粗。
10. 在纯文本编辑器中写好 `**==组合文字==**` 后普通粘贴，确认加粗＋高亮保留，复制和保存后再打开也不被强制单选。再选中这段点击斜体按钮，应替换成仅斜体。旧卡片中原有组合只打开/关闭时不清洗；标题、列表和对齐不参与行内单选。
11. 点击 `×` 左边的 `?`“编辑说明”，确认标题为“编辑说明”，以左对齐紧凑列表展示加粗、斜体、下划线、高亮、行内代码各自快捷键及简短语法（含字面 `<u>文字</u>`），无表头/网格线。黄色操作名只写“恢复普通输入”，去掉括号；该行中间是 `Ctrl/Cmd+\`，右侧语法分区放 `→`（片段末尾），所有语法与箭头从同一位置左对齐。英文版使用短文案 `Plain typing` / `at end`，约 300px 视口下该项保持单行，快捷键框不因其他文字换行而拉高。没有平台小字、Esc/双空格提醒或其他通用说明。窄侧边栏内容可换行但不横向溢出。保留选区或待输入格式打开/关闭说明，均不应变化；说明内 Esc 只关说明，不取消正文，输入法候选优先。
12. 键盘 Tab 到 `?` 后用 Enter/空格打开，说明能聚焦阅读，Esc 返回按钮；鼠标/触控可点开，再点 `?` 或外部关闭。说明打开时点画布空白，仍应正常保存退出。在窄侧边栏、深浅主题和全屏检查 `?`/`×` 可见、弹层不被裁切；切卡/删除/虚拟化后无残留说明。
13. 无选区输入高亮/加粗/颜色文字，或把光标放到链接末尾，按 Ctrl+\ / Cmd+\：相关格式按钮立即熄灭，再连续输入含空格、标点和中文的文字应为普通，已有内容和 URL 不变。标题、列表、引用、对齐、表格、代码块和卡片字号不变；复制/保存/重载后结果一致。不输入、只切普通再退出时，不产生内容保存；有选区时不清格式、不跳光标；输入法候选期间不截断输入。在真实 Windows/Linux、Mac、主用浏览器与常用键盘布局检查键位无冲突，编辑区之外不拦截。
14. 将光标放在高亮/加粗/颜色/行内代码/链接的片段末尾（分别测段末和后接普通文字），按一次 `→`，格式按钮熄灭，下一输入普通，已有文字、URL 和光标位置不变，不能插入空格/零宽字符；再按 `→` 正常移动。格式内部移动、Shift 扩选、Ctrl/Option/Meta 跳词、中文候选、代码块及混合 RTL 文字仍保持原生导航。组合片段末尾一次退出全部行内格式；只按方向键不输入后退出编辑不能造成无意义保存。

**通过标准：**只改变选中部分或后续输入；同一段新应用的行内格式单选，UI 与复制、保存后结果一致；选区不跳到别处；点击工具栏不会提前结束编辑；点外部后能退出，即使之前开过弹层；格式刷新后存在，无新增异常。

边框显示的是编辑器当前/下一输入的实际格式，不是最近点击记录，也不是鼠标 hover。不新增混合选区半选态或双空格退出。工具操作采用单选，手写语法、粘贴和导入保留组合，不以“保护数据”为理由静默删除用户已有或明确写出的格式。

逐字输入复杂嵌套语法的即时转换仍受 Tiptap 原有输入规则限制；本轮不新增整行重解析，不承诺所有嵌套组合都能在最后一个符号键入时完整预览。需要验证组合的源码解析时，使用普通 Markdown 粘贴或导入路径；不要把不完整的即时预览当作格式被互斥策略清除。

### T03 中文输入法与撤销/重做【必测；A/T/P】

1. 使用实际中文输入法，连续输入 `这是中文输入测试，注意：请先备份。`；中间移动光标、插字、退格。
2. 先输入一段已上屏正文，再开始另一段拼音但不要选词，按 Esc 取消候选，继续输入。
3. 输入 `第一段`，停 1 秒，再输入 `第二段`；按一次撤销，再按重做。macOS 用 Cmd+Z / Cmd+Shift+Z；Windows 用 Ctrl+Z / Ctrl+Y。
4. 中文、英文和表情混排后保存刷新。

**通过标准：**不吞字、不重复上屏、不切断拼音；候选期间 Esc 只取消候选，不退出/清空整条备注；一次撤销不会同时撤掉两次已分组输入；重做可恢复。

> 没有候选时，当前 Esc 行为不同：T 放弃本轮备注编辑，P 提交退出（有弹层时可能先处理弹层），A 提交退出。本轮未统一这些语义；不要拿普通 Esc 当四类对象通用的保存按钮。退出编辑后再次进入，撤销历史不要求跨会话保留。

### T04 实体、尖括号与代码【必测；A/T/P】

1. 手输第 3.2 节的一行，或明确使用“粘贴为纯文本”，保存刷新 3 次。不要用普通 Markdown 粘贴替代这一步。
2. 在“QA-实体与代码”修改代码块以外的一处普通文字；保存刷新。
3. 检查代码中的 `&lt;span&gt;`、`## ## literal` 和内层三个反引号是否还在；复制代码回纯文本编辑器核对。

**通过标准：**显示字符与复制结果符合原内容；实体不继续解码；代码不被当标题或 HTML；不能丢字。

### T05 表格往返【必测；样例 A，T/P 各复用一次】

1. “QA-表格”第一张表中，编辑 `x | y` 所在单元格；同样试行内代码和加粗的竖线。
2. 修改合并单元格表、多段落单元格中的一个字。
3. 保存刷新后导出，重新导入测试 Profile，再核对。

**通过标准：**仍是两列，`z` 不丢；加粗和代码保留；复杂表格不被压平；不因保存导致新列/错列。导出允许复杂表格使用 HTML，不强制全部转成 GFM。

### T06 折叠块与历史格式【必测；样例 A，T/P 复用】

1. 给样例导出一份“修改前”包；只进入编辑然后退出，不改字，再导出。
2. 对比该卡 `text` 字段，而不是要求整个包字节一致（时间戳等会变）。
3. 在折叠块内改一个词，保存刷新；展开/收起并检查嵌套块、摘要和正文。
4. 检查旧 `<font color>`、`<center>`、带对齐段落中的加粗/高亮。

**通过标准：**仅进入/退出不改原始文字源码；真正编辑后仍保留折叠结构及 rich text；对齐块中不能出现字面 `**加粗**`。编辑器允许规范化 HTML 标签写法，但不能丢语义/内容。

### T07 静态待办精确更新【必测；A/T/P，C 抽查】

1. 先退出编辑，在观察态分别勾选引用任务、父任务、子任务、普通任务，每次刷新核对。
2. 父项勾选后看子项，子项勾选后看相邻项；不要求父子自动级联。
3. 检查代码块内的 `- [ ]` 不应变成可点击任务。
4. 用“QA-链接与混合待办”分别勾选 HTML 任务和后面的 Markdown 任务。

**通过标准：**只改用户点中的那一项；刷新后 UI 与源码一致；不能点第一项却改第二项；HTML 与 Markdown 混排也不串位。

### T08 清空、撤销、删除和重建【必测；仅测试数据】

1. T/P 输入内容后，用清空按钮确认清空；点外部，刷新，再打开。
2. 在另一条备注上清空后先按撤销。若明确执行撤销，恢复原内容是合理的；随后退出刷新，应与撤销后的显示一致。
3. 编辑一张测试卡后，用正常删除操作删掉；刷新并等待后台更新，确认没复活。
4. 在测试 Profile 中，用样例包替换一次画布，再刷新；旧测试卡不应因异步回写复活。

**通过标准：**未主动撤销的清空不会自己恢复；删除/替换不会被旧编辑器回写；其他卡片不受影响。

### T09 链接与图片【必测；A/T/P】

1. 粘贴 `https://example.com`、`www.example.com` 和 `[测试链接](https://example.com)`；保存后点击。
2. 准备一张小于 20KB 的 PNG 图标，粘贴/拖入编辑区；保存刷新。
3. 再用一张大于 20KB 的图片走同样的文件粘贴路径。

**通过标准：**链接可点击，不渲染成图片；小图保留，不变成 Base64 正文；超限时给出限制提示，已有正文不损坏。20KB 是当前文件粘贴限制，不要求所有外部图片 URL 都按这个限制拒绝。

### T10 侧边栏、页面和卡片全屏【必测】

1. 先只在独立画布页面执行 T01，再只在侧边栏执行 T01。
2. 将 A/T/P 分别全屏，输入、选字、改色、滚动到文末，退出全屏，再刷新。
3. 同时打开页面和侧边栏，但**一次只在一处编辑**；页面保存后看侧边栏，反向也测。
4. A/T/P/C 在卡片全屏时手动点格式按钮，确认一次打开、再次关闭，`?`、颜色、标题、列表和对齐菜单均可操作；打开目录/锚点侧栏，浮窗及子菜单不能被侧栏挡住。分别从窄侧边栏拓宽、从独立页面缩窄：按钮与间距先切紧凑排布，再适当缩小（不低于 80%）；可用画布宽约 300px 时应能一行显示全部格式按钮，`×` 不单独掉到第二行，更窄确实放不下才换行。`?`/`×` 不出可见区域；空白卡底部外层悬浮工具窗的按钮和缩放控件也应收紧为一行，不裁切、不省略操作，拓宽后恢复常规尺寸。
5. 工具窗打开期间切入/退出卡片全屏，调整卡片布局缩放（例如 80%、130%）、折叠/展开目录侧栏和拖动侧栏宽度，位置应跟随可用画布区域更新。工具窗按屏幕尺寸适配，不随正文被额外放大；完成后退出编辑/删除/切卡，颜色盘、说明和顶层浮窗无残留。以上还需在实际浏览器全屏模式下复测。

**通过标准：**内容与格式一致；焦点不跳出卡片；滚动不频繁回顶部；退出全屏后大小位置合理；已保存内容可在另一个视图看到。若不同步，记录延迟和操作顺序。

并发编辑同一段、远端覆盖正在输入的内容可做探索测试，但不能假设本轮已经实现冲突合并；出现输入被覆盖仍要记录为数据风险。

### T11 浅色/深色和布局【必测；抽查即可】

切换浅色/深色，缩放画布，调整卡片宽高；查看代码块、高亮、待办、表格和长段落。

**通过标准：**文字可读；已勾选任务与未勾选可区分；代码块不变成行内小底框；表格和横向滚动可用；编辑前后无大片意外空行或遮挡。

### T12 虚拟化恢复与生命周期【必测；约 10～15 分钟】

1. 准备 20 张左右文字卡、5 个带备注的临时栏目、5 个永久栏目副本，分散到多个视口。
2. 编辑并保存其中几张；确认退出编辑、取消选中，再平移到远处。
3. 等待设置里的离屏卸载延迟结束，再额外等 2 秒；默认延迟约 6 秒，可能另有防抖，不要移动 1 秒就认为已卸载。
4. 回原位置，检查内容并再次编辑；往返 10 次，再刷新。

**通过标准：**卡片能恢复；内容无变化；点击一次不会触发重复弹层/重复保存；不逐轮变卡；活跃编辑器和全局监听不随往返次数累积。选中、全屏、仍有焦点的卡片可能刻意保留，不能据此判断卸载失败。

### T13 导出/导入与原生节点【必测；仅测试 Profile】

1. 修改各测试卡并保存，导出完整测试包，保留为 B。
2. 在另一份测试 Profile 或已备份的测试环境中导入 B，再逐张核对实体、代码、表格、折叠与待办。
3. 记录“QA-原生文字节点”导入完成后的 ID（追加导入可能有正常的去重映射），改字再导出，检查对应节点仍是 `type: "text"`，内容与这次导入后的 ID 没有意外变化。

**通过标准：**内容与格式可往返；原生节点不被错误改成其他卡片类型。不要要求包内所有 UI 设置都一并恢复，本项目的布局/视图状态有独立持久化边界。

### T14 较大画布体验【建议；硬件允许时】

分两档测：先 20 张文字卡；再 100 张文字卡 + 20 个带备注的栏目/副本。重复输入、拖选、平移、缩放、退出编辑，比较体验。

**通过标准：**没有持续漏字、数秒级无响应或循环卡死；同样的往返操作不无限增加内存/实例。记录卡片数、设备和耗时，不用“内存必须少于固定 MB”作为跨设备硬标准。

## 6. 可选：不用改数据的 Console 辅助检查

不熟开发者工具可以跳过；不要运行清库、改 storage、直接 new Editor 等脚本替代手工操作。

### 6.1 真正的活跃编辑器数量

退出所有编辑、退出卡片全屏后，在当前画布页面 Console 执行：

```js
new Set(
  [...document.querySelectorAll('.md-canvas-node, .md-canvas-editor, .temp-node-description, .permanent-section-tip')]
    .map(el => el.__tiptapInstance)
    .filter(instance => instance && !instance.isDestroyed)
).size
```

预期：全部退出后为 **0**；只编辑一处时通常为 **1**；再退出回到 **0**。这只统计当前文档中可达的实例，不是完整的内存泄漏证明。

**不要数 `.tiptap.ProseMirror` 元素**：静态阅读态也使用这个类名，数量不等于编辑器实例数。

### 6.2 永久备注的 document 监听器

Chrome/Edge 开发者工具 Console 专用（不是网页通用 API）：

```js
(getEventListeners(document).mousedown || [])
  .filter(entry => entry.listener.name === 'onPermanentDocMouseDown').length
```

在同一视口、同样的永久栏目副本数下，记录初值，执行 T12 后再看。它允许随已渲染永久卡数量变化，但不应每往返一次就多一批。不是要求始终为 0，也不要用 document 总监听器数判断这项修复。

## 7. 最后如何判断能不能用/发版

- **不通过，先停用测试版**：正常保存后丢字/变字、表格串列、勾错任务、清空/删除复活、编辑无法退出/再次进入、出现可稳定复现的数据覆盖。
- **发版前必须处理或明确限制**：重复操作让实例/监听器持续累积；常用交互明显卡死；主用浏览器/侧边栏保存失败。
- **可单独记录后排期**：纯视觉间距问题、轻微样式差异、不影响内容的源码规范化。
- 完整验收至少满足：Q1～Q8 全通过；T01～T13 无阻塞问题；换 Profile 导出/导入通过；Console 无与这些操作相关的新增未捕获异常。
- 所有步骤标记为“通过/失败/未测/不适用”，不要把未测默认为通过。

以下不应仅凭本轮测试就宣布完成：完整 Obsidian Wikilink/Callout 交互、协同冲突合并、所有旧数据自动修复、全量持久化性能优化、任意 HTML 无损编辑。
