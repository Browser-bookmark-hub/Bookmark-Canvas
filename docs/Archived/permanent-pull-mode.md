# 永久栏目拉取方式（最终方案）

> 返回文档索引：[docs/README.md](./README.md)

## 1. 目标

仅针对“云端 -> 本地”时的**永久栏目**（浏览器真实书签树）新增两种应用方式：

- 覆盖恢复
- 增量同步（仅增删）

临时栏目、空白栏目不使用本方案，继续沿用原有同步逻辑。

---

## 2. UI 放置

放在同步二级 UI 的 **2. 插件专属** 区域。

设置名称：`永久栏目拉取方式`

附加参数：`增量同步阈值`（仅自动模式使用）

可选值：

- `自动`
- `自动`
- `覆盖恢复`
- `增量同步（仅增删）`

说明：

- 仅影响云端 -> 本地时永久栏目的处理方式。
- 默认推荐使用 `自动`。
- 自动：阈值以下使用增量同步，阈值以上使用覆盖恢复。
- 首次同步（云端为准）也会先做同一套永久栏目差异判断：完全一致时跳过；否则按当前拉取方式决定增量同步或覆盖恢复。
- 增量同步只做新增和删除；检测到复杂变化时，自动回退到覆盖恢复。

---

## 3. 两种方式

### 3.1 覆盖恢复

用于：

- 首次同步（云端为准，且判断结果需要覆盖时）
- 大规模变化
- 复杂变化
- 增量判断失败时的回退

行为：

- 清空本地永久栏目
- 按云端恢复出的完整树重建

### 3.2 增量同步（仅增删）

用于：

- 后续小规模拉取
- 仅拉取
- 不一致面板用云端覆盖本地
- 冲突面板用云端覆盖本地
- 立即同步里最终进入 remote pull 的分支

行为：

- 先把云端永久栏目文件完整解析成树
- 再和本地浏览器书签树比较
- 只执行：
  - 新增
  - 删除

不单独实现：

- 修改
- 移动
- 重排

其中：

- 整个文件夹删除：直接 `removeTree`
- 整个新增文件夹分支：先创建文件夹，再递归创建其子节点

---

## 4. 如何判断路径和位置

不依赖 markdown 文本 diff 区块，也不依赖 canvas 坐标。

统一原则：

- 先把云端永久栏目完整解析成树
- 路径 = 父子关系链
- 位置 = 同一父节点下的兄弟顺序

也就是说：

- 要知道某个新增书签该放到哪里，必须先知道它的父文件夹是谁
- 只看局部文本变化块，无法稳定知道完整上下文
- 因此永久栏目增量同步必须基于**完整文件 -> 完整树**来做

---

## 5. 动态阈值

增量同步不是始终使用，而是按变化规模自动判断。

当前默认阈值：

- 用户可调绝对阈值：默认 `200`

说明：

- 按新增 / 删除的节点数计算
- 不是只看书签数，文件夹及其子项也会计入

如果本次逻辑变化量超过该阈值，则自动回退为覆盖恢复。

---

## 6. 复杂变化回退条件

以下情况不走增量，直接回退覆盖恢复：

- 检测到重排
- 无法稳定判断父级或上下文
- 变化量超过动态阈值
- 云端永久栏目树解析失败

---

## 7. 入口对齐范围

本方案只对“云端 -> 本地”的永久栏目应用方式生效。

已接入或计划接入的入口：

- 首次同步（云端为准） -> 复用同一套永久栏目判断：same 跳过，其余按增量/覆盖策略执行
- 仅拉取
- 冲突面板：使用云端覆盖本地
- 不一致面板：使用云端覆盖本地
- 立即同步里最终进入 remote pull 的路径

自动拉取相关入口是否强制采用同一策略，后续可继续对齐。
