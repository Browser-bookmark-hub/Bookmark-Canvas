# 三个同步面板 UI 统一方案（首次同步 / 云端不一致 / 冲突）

> 返回文档索引：[docs/README.md](./README.md)
> 
> 来源：从 `docs/permanent-root-meta-plan.md` 中拆出的独立 UI 方案文档。

## 1. 目的

本文只讨论三个同步面板的 UI 表达，不讨论底层 Git / SHA / dirty / 内部文件级实现细节。

范围包括：

- 首次同步面板
- 云端不一致面板
- 冲突面板

当前目标：

- 三个面板统一成同一套理解模型
- 用户始终只看两块：
  - 永久栏目（浏览器书签）
  - 其他同步数据
- 按钮只负责“怎么处理”
- 面板本身先负责“哪里出了问题”

---

## 2. 统一原则

### 2.1 统一结构

三个面板统一采用以下结构：

1. 面板标题
2. 一句人话总结（直接说哪里一致、哪里有变化、哪里有冲突）
3. 两个纵向表格区块：
   - 永久栏目（浏览器书签）
   - 其他同步数据
4. 每个表格统一列结构：
   - 对比项
   - 本地
   - 云端
5. 每个表格最后一行统一为：
   - `整体内容与结构`
   - 这一行不再左右重复写两份，只保留一个合并结果

### 2.2 主 UI 只展示什么

主 UI 中只展示：

- 数量
- 整体内容与结构
- 最新修改时间

主 UI 中不再直接展示：

- `backup`
- `文件级比较`
- `状态项比较`
- `仅本地文件`
- `仅云端文件`
- `画布文件数`
- 只给普通用户看的主面板里，不再把 hash 当成核心信息

说明：

- hash、文件级冲突数、内部 dirty 明细，可以继续留在内部逻辑或调试层
- 但不应成为三个主面板的主 UI 表达

### 2.3 主文案统一词汇

主 UI 中统一使用：

- `结果：一致`
- `结果：有变化`
- `结果：有冲突`
- `整体内容与结构`
- `最新修改时间`

---

## 3. 首次同步面板

### 3.1 面板结构

首次同步面板保留：

- 顶部一行：`云端最新修改时间`
- 然后进入两个标准表格

### 3.2 永久栏目表格

对比项固定为：

- 根目录数
- 文件夹数
- 书签数
- 整体内容与结构

### 3.3 其他同步数据表格

对比项固定为：

- 临时栏目数
- 空白栏目数
- 整体内容与结构

### 3.4 结论区要求

当前结论区只说人话，例如：

- 永久栏目已一致，本次不会改动浏览器书签；只需要决定其他同步数据以谁为准。
- 其他同步数据已一致；只需要决定永久栏目以谁为准。
- 永久栏目和其他同步数据都存在差异，请先确认同步方向。
- 永久栏目和其他同步数据都已一致，本次主要用于建立首次同步基线。

---

## 4. 云端不一致面板

### 4.1 核心问题

云端不一致面板必须回答的问题不是“有不一致”，而是：

- 永久栏目哪里不一致
- 其他同步数据哪里不一致

因此它要直接复用首次同步的那套两表结构，而不是只显示 hash 或一句抽象提示。

### 4.2 表格要求

- 永久栏目表格：与首次同步一致
- 其他同步数据表格：与首次同步一致
- `最新修改时间` 放在每个表格的第一行

也就是：

- 永久栏目表格第一行：最新修改时间
- 其他同步数据表格第一行：最新修改时间

### 4.3 结论要求

面板顶部的人话总结必须直接说：

- 永久栏目一致 / 有变化
- 其他同步数据一致 / 有变化

例如：

- 检测结果：永久栏目一致；其他同步数据有变化。请先确认处理方向。
- 检测结果：永久栏目有变化；其他同步数据一致。请先确认处理方向。
- 检测结果：永久栏目有变化；其他同步数据有变化。请先确认处理方向。

---

## 5. 冲突面板

### 5.1 核心问题

冲突面板必须回答的问题不是“发生冲突”，而是：

- 永久栏目是不是冲突
- 其他同步数据是不是冲突

因此它也要复用同一套两表结构，而不是只保留原来那种“本地 / 云端 hash + 大小”的简化对比。

### 5.2 表格要求

- 永久栏目表格：与首次同步一致
- 其他同步数据表格：与首次同步一致
- `最新修改时间` 放在每个表格的第一行

### 5.3 冲突语义要求

每一块的结果语义应允许出现三种状态：

- 一致
- 有变化
- 有冲突

其中冲突面板里，如果某一块确实已经构成并发冲突，则显示：

- `结果：有冲突`
- `整体内容与结构：存在冲突`

如果某一块并未冲突，只是另一块冲突，则该块仍然可以显示：

- `结果：一致`
- 或 `结果：有变化`

不能整个面板一律粗暴写成“全部冲突”。

### 5.4 结论要求

面板顶部的人话总结必须直接说：

- 永久栏目存在冲突 / 一致 / 有变化
- 其他同步数据存在冲突 / 一致 / 有变化

例如：

- 检测结果：永久栏目存在冲突；其他同步数据存在冲突。请先确认处理方向。
- 检测结果：永久栏目存在冲突；其他同步数据一致。请先确认处理方向。
- 检测结果：永久栏目一致；其他同步数据存在冲突。请先确认处理方向。

---

## 6. 时间信息放哪

当前定稿：

- 首次同步面板：
  - 保留顶部单独一行 `云端最新修改时间`
- 云端不一致面板：
  - `最新修改时间` 放进表格第一行
- 冲突面板：
  - `最新修改时间` 放进表格第一行

时间来源：

- 本地最新修改时间：本地快照 `updatedAt` / 最近一次本地有效修改时间
- 云端最新修改时间：当前同步路径在云端仓库上的最新提交时间

## 8. 最终目的

这三个面板最终要做到：

- 用户不需要理解内部同步实现细节
- 用户只需要回答两个问题：
  1. 永久栏目是不是一致 / 有变化 / 有冲突
  2. 其他同步数据是不是一致 / 有变化 / 有冲突

然后再决定：

- 以云端为准
- 以本地为准
- 稍后处理

也就是说：

- 面板先负责把“哪里出了问题”讲清楚
- 按钮再负责让用户选择“怎么处理”
- 不能反过来先给按钮、再让用户自己猜哪里不一致
