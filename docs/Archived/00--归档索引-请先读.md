# 归档索引

本目录只保存历史开发计划、复审记录、测试方案与样例，按发布版本号划分目录，并在各版本目录内以数字序号组织。后续开发者或 AI 读取本仓库时，应以 `Bookmark-Canvas-main/` 的当前代码与 `docs/` 根目录留存的现行文档为唯一事实来源；这里的归档文档不能直接替代当前实现规范。

整理基准：2026-11-26（准备发布 `v1.5.0`，上一已发布生产基线为 `v1.0.4`）。

## 使用规则

- 需要理解当前行为时，先看 `Bookmark-Canvas-main/` 的代码与 `docs/` 根目录文档（`限制与妥协.md`、`初始引导.md`、`路线图与架构演进思考.md`、`后续跟踪-浏览器根模型与GitHub哈希.md` 及各自英文版）。
- 需要理解某个功能在对应版本周期为何这样设计或验收时，再按版本查看本目录。
- 文档标题或状态栏中的标注优先于正文旧描述；正文里出现的“当前”“待实施”“计划”“唯一权威”等字样仅反映当时撰写基线，可能已被后续提交演进或替代。
- GitHub/Obsidian 旧远程同步、应用级同步元信息、旧 manifest/dirty/pathMap 设计以及 `originPermanent` / `sequenceNumber` 旧字段不代表当前架构。
- favicon 权限仍由当前代码中的 `FaviconCache`、后台 favicon fetch、manifest `favicon` / `<all_urls>` 决定，不以后续旧计划文字为准。

## 版本目录结构

- `v1.0.4/`：`v1.0.4` 及以前版本的历史归档文档（`01`～`18`，包含 `v1.0.0` 前后开发期的架构与计划记录）。

## 当前代码事实摘要

- GitHub 推送/拉取存在于 `history_html/transfer_AI_sync/`，是完整画布包传输，不是旧 Obsidian Git 自动同步。
- 旧 `CanvasObsidianGitSync`、`canvasGit*`、`bcs-sync-manifest.json`、dirty/pathMap/恢复锁式远程同步状态机当前不存在。
- Note/Tag 永久元数据仍在 `bcs:perm:main.identityMap[*]`，临时栏目 note/tag 在 item 内联字段；临时栏目已移除 `originPermanent` 与 `sequenceNumber`。
- 导出沙盒会把永久树 Chrome ID 转为 `syncId`，identityMap 只保留有扩展字段的条目。
- 临时栏目 BCS 已按 `bcs:canvas` + `bcs:section:<id>` 分片，普通内容变化走 section patch。
- 画布富文本与 Mermaid 渲染已基于 TipTap v3（`tools/build-tiptap-bundle/`）与 Pele.js（`tools/build-pele/`）实现。
- 画布浏览统计（`@热度` / `@最近` / 右键信息）采用 IndexedDB `schemaVersion: 4` 按天分桶账本与双引擎自适应扫描（`history_html/search/history_stats_service.js`）。
- Favicon 系统由前台 `FaviconCache`、后台 tab favicon 广播、浏览器 `/_favicon/` 和多源 fallback 组成；`favicon` 权限与 `<all_urls>` 仍有当前用途。
