# 归档索引

本目录只保存历史开发计划、复审记录和需求源流。后续开发者或 AI 读取本仓库时，应以当前代码为唯一事实来源；这里的文档不能作为当前实现规范直接引用。

整理基准：2026-07-04 当前代码现状。

## 使用规则

- 需要理解当前行为时，先看 `Bookmark-Canvas-main/` 的代码。
- 需要理解某个功能为什么曾经这样设计时，再看本目录。
- 文档标题中的状态优先于正文旧描述；正文里出现的“当前”“计划”“唯一权威”等字样可能已经过时。
- GitHub/Obsidian 旧远程同步、应用级同步元信息、旧 manifest/dirty/pathMap 设计不代表当前架构。
- favicon 权限仍由当前代码中的 `FaviconCache`、后台 favicon fetch、manifest `favicon` / `<all_urls>` 决定，不以后续旧计划文字为准。

## 当前代码事实摘要

- GitHub 推送/拉取存在于 `history_html/transfer_AI_sync/`，是完整画布包传输，不是旧 Obsidian Git 自动同步。
- 旧 `CanvasObsidianGitSync`、`canvasGit*`、`bcs-sync-manifest.json`、dirty/pathMap/恢复锁式远程同步状态机当前不存在。
- Note/Tag 永久元数据仍在 `bcs:perm:main.identityMap[*]`，临时栏目 note/tag 在 item 内联字段。
- 导出沙盒会把永久树 Chrome ID 转为 `syncId`，identityMap 只保留有扩展字段的条目。
- 临时栏目 BCS 已按 `bcs:canvas` + `bcs:section:<id>` 分片，普通内容变化走 section patch。
- 预置模板、卡片组、组导出、AGENTS/CLAUDE 指南已落地并继续演进。
- Favicon 系统由前台 `FaviconCache`、后台 tab favicon 广播、浏览器 `/_favicon/` 和多源 fallback 组成；`favicon` 权限与 `<all_urls>` 仍有当前用途。
