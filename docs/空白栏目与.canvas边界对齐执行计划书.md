# Bookmark-Canvas 空白栏目与 .canvas 边界对齐执行计划书

> 返回文档索引：[docs/README.md](./README.md)
> 返回总顺序计划：[存储收敛与JSON模式总顺序计划书](./存储收敛与JSON模式总顺序计划书.md)
> 参考文档：[Markdown-First 同步数据模型规划书](./sync-plan-markdown-first-data-model.md)

## 1. 这份计划书要解决什么问题

第二刀不处理永久栏目、临时栏目、`JSON模式（供AI）` 本身。

第二刀只处理两件事：

- 插件空白栏目正文的真相源
- `.canvas` 与当前导出结构之间的边界语义

目标不是把整套插件运行时重写成 Obsidian 原生 `nodes[]`。

目标是先把这一条线锁死成：

- 正文归 `.md`
- 布局归 `.canvas`
- HTML 只做运行时渲染

这样做的直接收益是：

- 导入、导出、同步时更容易溯源
- 内容改动和布局改动更容易分离
- 文件 diff 更稳定
- 少掉“先存 HTML、导出时再转 Markdown”造成的漂移

## 2. 当前结论

### 2.1 空白栏目

插件空白栏目后续固定为：

- `markdownSource`：正文唯一真相源
- `html`：运行时渲染缓存 / 编辑态缓存
- `text`：预览、标题提取、兜底字段

也就是：

- 持久化主字段改成 `markdownSource`
- 页面里继续显示 HTML 富文本效果
- 但 HTML 不再是持久化正文真相源

### 2.2 `.canvas`

`.canvas` 在第二刀里的职责固定为：

- 只负责布局与节点语义
- 不负责插件空白栏目正文真相源

第二刀锁死的外部语义是：

- `file` 节点：路径、坐标、尺寸、颜色
- `text` 节点：原生 Obsidian 文本正文
- `group` 节点：分组壳
- `edges`：连接关系

### 2.3 插件内部运行时

第二刀明确不要求立刻把内部改成单一 `nodes[]` 模型。

当前运行时桶结构先保留：

- `tempSections`
- `mdNodes`
- `edges`

也就是：

- 外部边界向 `.md + .canvas` 对齐
- 内部运行时暂时继续保留现有桶结构

## 3. 第二刀不做什么

- 不改永久栏目主内容真相源
- 不改永久栏目副本结构
- 不改临时栏目 `items` 主结构
- 不提前接入 `JSON模式（供AI）`
- 不提前把 `obsidianExportFormat` 改成三值
- 不重做整套导入 / 导出 / 同步总架构

## 4. 执行顺序

### 4.1 第一步：空白栏目数据模型落地

- 给插件空白栏目补 `markdownSource`
- 保存时以 `markdownSource` 为主
- `html / text` 暂时保留，作为运行时派生字段和兼容读侧字段

这一阶段先不追求删干净旧字段，先把真相源换掉。

### 4.2 第二步：空白栏目渲染链改成 Markdown-first

- 打开空白栏目时：`markdownSource -> html`
- 页面里继续通过渲染器显示成当前 HTML 效果
- 编辑完成时：把编辑器内容回写成 `markdownSource`

也就是：

- 显示继续是 HTML
- 存储改成 Markdown

### 4.3 第三步：空白栏目导出 / 导入改成直接走正文真相源

- 导出 `.md` 时直接写 `markdownSource`
- 不再依赖 `node.html -> markdown`
- 导入 `.md` 时直接恢复 `markdownSource`
- 首次渲染时再生成 `html`

### 4.4 第四步：`.canvas` 边界对齐

- 把当前导出时使用的 `.canvas` 节点语义固定下来
- 插件空白栏目继续映射到 `file` 节点
- 原生 text 卡片继续映射到 `text` 节点
- `group / edges` 继续沿用当前导出语义

这里做的是“小边界对齐”，不是大规模重构运行时。

### 4.5 第五步：再清理旧 HTML-first 路径

只有在下面这些都跑通后，才清旧链路：

- 空白栏目保存稳定
- 空白栏目导出稳定
- 导入后能完整恢复
- `.canvas` 改动与 `.md` 改动分离正常

到这一步再考虑移除：

- 仅为导出而存在的 `html -> markdown` 旧路径

## 5. 第二刀的关键边界

### 5.1 插件空白栏目 vs 原生 text 卡片

这两者必须继续分开：

- 插件空白栏目：正文真相源是 `.md`
- 原生 text 卡片：正文真相源是 `.canvas`

不能为了统一而强行把它们混成一套正文协议。

### 5.2 内容改动 vs 布局改动

第二刀完成后，理想行为应当是：

- 改空白栏目正文：主要改 `.md`
- 移动卡片 / 调整尺寸 / 连线：主要改 `.canvas`

这正是第二刀最重要的收益之一。

### 5.3 先边界对齐，不先全量收口

第二刀优先做的是：

- 真相源切换
- 导入导出边界固定
- `.canvas` 语义固定

不是：

- 一次性重写全局存储
- 一次性改掉所有运行时对象

## 6. 验收标准

- 插件空白栏目本地持久化时，`markdownSource` 成为正文真相源
- 空白栏目导出 `.md` 不再依赖 `node.html -> markdown`
- 导入 `.md` 后可以恢复 `markdownSource`
- 插件空白栏目与原生 `text` 卡片仍能区分
- `.canvas` 继续负责位置、尺寸、节点类型、连线
- 修改正文时，不应无意义抖动 `.canvas`
- 修改布局时，不应无意义抖动空白栏目的 `.md`

## 7. 与后续计划的关系

- 这份计划书服务于总顺序计划的第二刀
- 它是后续导入 / 导出 / 同步变薄的重要前置条件
- 它不替代 `JSON模式（供AI）` 主计划
- 它也不替代永久栏目 / 临时栏目协议层子计划

一句话总结：

- 第二刀不是重做 Canvas
- 而是先把空白栏目这条线做成“正文归 `.md`、布局归 `.canvas`”
