## 1. 当前边界（最终口径）

空白栏目与 native text 已统一协议，使用同一条正文链路：

1. 正文真相源：`.canvas` 的 `type: "text"` 节点（`text` 字段）。  
2. `html`：仅运行时渲染/编辑缓存，不是持久化真相源。  
3. 不再维护空白栏目独立 `.md` 镜像文件。  

一句话：**空白正文与布局都随 `.canvas` 走，导入/导出/同步同源。**

## 2. `.canvas` 节点语义（导出/导入/同步）

1. 空白栏目 / native text：`text` 节点。  
2. 永久栏目、临时栏目等卡片：`file` 节点。  
3. 分组壳：`group` 节点。  
4. 连线：`edges`。  

以上语义在本地保存、导入导出、同步上传中保持一致。

## 3. 运行时与交互口径

1. 运行时结构继续保留 `tempSections / mdNodes / edges` 分桶。  
2. 编辑器是“视觉编辑 + 源码展开”模式：点击对应渲染块时只展开当前块源码，其他内容保持渲染态。  
3. 保存时正文回写到节点 `text`，随后进入统一的 `.canvas` 持久化链路。  

## 4. 脏标记与同步口径

1. 空白正文编辑会记录 `blankIds`。  
2. 同步层将 `blankIds` 映射到 `.canvas` 路径。  
3. 同步成功后，`dirty.blank` 与 `dirty.canvas` 一并清理。  

## 5. 验收标准（以现行实现为准）

1. `bcs:md:*` 不再承载空白正文链路。  
2. 导出包中没有空白栏目独立文件夹文件。  
3. `.canvas text` 节点数量与运行时空白栏目数量一致。  
4. JSON 导出与云同步上传产物一致。  

## 6. 非目标

1. 不把运行时强改为单一 `nodes[]` 模型。  
2. 不重开“空白正文拆回 `.md` 分片”路线。  
3. 不改永久栏目/临时栏目既有协议主线。
