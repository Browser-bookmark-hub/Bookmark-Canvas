# 临时栏目标签化：移除序号与永久来源关系

## 目的

临时栏目协议目前同时持久化 `label`、`originPermanent` 和 `sequenceNumber`。后两者要求第三方编辑 JSON 时理解并维护插件内部状态，且在导出 JSON 的尾部形成额外元数据。

本设计的目标是让 `label` 成为第三方唯一需要维护的临时栏目语义字段：第三方编辑、BCS 本地存储、JSON/Markdown 导入导出都不再写入 `originPermanent` 与 `sequenceNumber`。技术主键 `id` 仍保留，用于 Canvas 节点、BCS 分片、DOM 和连线；`id` 是唯一性与引用完整性的唯一依据，`label` 可以重复。

本文件是实施前设计，不代表本次已经修改代码或协议。

## 已确定的标签规则

| 栏目类别 | 目标 `tempKind` | 目标标签 | 分裂后的标签 | 外观设置 |
| --- | --- | --- | --- | --- |
| 从永久栏目拖入的常规栏目 | `regular` | `A-1`、`B-1` 等 | `A-1-1`、`A-1-2` | 常规临时栏目尺寸和颜色 |
| 常规栏目的继续分裂 | `regular` | 保留父标签 | 父标签加 `-N` | 常规临时栏目尺寸和颜色 |
| 空白处新建临时栏目 | `special` | `{新建}` | `{新建}-1`、`{新建}-1-2` | 特殊临时栏目尺寸和颜色 |
| 导入、拖入、搜索、批量、粘贴、添加、AI 等 | `special` | 例如 `{导入}`、`{拖入}`、`{搜索}`、`AI` | 例如 `{导入}-1`、`{导入}-1-2` | 特殊临时栏目尺寸和颜色 |

`{新建}`、`{导入}` 中的花括号属于显示标签的一部分。ID 生成仍使用现有的安全字符规范化，例如 `{新建}` 可对应 `temp-section-新建`；分裂标签必须保留原始显示标签。

特殊栏目分裂后必须保持 `tempKind: "special"`，并继承特殊栏目尺寸、颜色和颜色锁策略。不能仅因标签变成 `{导入}-1` 就被重新识别为常规栏目。

同名特殊栏目可以并列存在，例如可以有多个 `{导入}`。分裂关系只由创建时指定的父栏目决定，不通过全局 label 查找父栏目；其子标签使用父标签追加 `-N`。重复 label 的栏目必须用各自的 `id`、item `sectionId`、Canvas edge 和 BCS 分片 key 区分。

从永久栏目或永久栏目副本拖出时，只在创建瞬间读取来源槽位以分配 A/B/AA 标签族和复制内容。创建成功后，临时栏目完全独立：永久栏目副本的删除、重排或找不到都不得改变、删除或重新命名该临时栏目。

临时栏目 JSON 继续使用 `schemaVersion: 2`。读取旧 section 中的 `originPermanent` 与 `sequenceNumber` 时直接忽略，不做主动迁移或清洗；当前版本新建及重新生成的协议不再写入这两个字段，也不为此单独升级协议版本。

## 现状与目标

| 名称/路径 | 当前现状 | 目标状态 | 实现办法 |
| --- | --- | --- | --- |
| `label` | 常规栏目允许缺失；UI、目录和搜索用 `sequenceNumber` 生成 `A-1` 兜底 | 每个临时栏目均有非空显式 `label`；允许同名 | 统一在创建、导入和既有数据清理时补齐；外部无 label 数据使用固定协议值 `{unknown}`；删除所有显示层回退 |
| `sequenceNumber` | 创建时递增；用于标签回退、ID 回退、目录排序、搜索索引、恢复计数器 | 不再存在于运行时栏目、BCS 或导出协议 | 用标签自然排序和标签分配器替代；删除全局序号及重排逻辑 |
| `originPermanent` | 记录临时栏目来自主永久栏目还是副本；用于来源徽标、搜索多列判断和删除副本时清理关联 | 不再持久化来源关系 | 在创建瞬间使用拖拽上下文选定标签族；后续仅从 `label` 前缀显示/搜索 |
| 常规栏目标签分配 | 主永久栏目/副本通过 `originPermanent` 选择 A/B 族；无来源时走序号 | 仅在创建瞬间读取永久栏目槽位，扫描同族标签取下一个 `N` | 新增标签分配器；完成 `label` 写入后立即丢弃来源上下文；后续永久栏目变化不回写临时栏目 |
| 特殊栏目标签分配 | 已多为显式标签，但仍通常写入 `sequenceNumber` | 始终显式标签，支持基于标签的分裂 | 新建使用 `{新建}`；各种来源使用固定显示标签；分裂统一由父 `label` 追加 `-N` |
| 栏目 ID | `buildTempSectionIdFromMeta()` 无标签时用 `sequenceNumber` 生成 `temp-section-A-1` | ID 只以显式 `label` 或保留的现有 `id` 工作 | 删除序号回退；输入无 label 时补 `{unknown}`，再保持/生成 ID |
| 特殊栏目分类 | 来源集合可识别特殊栏目；空白新建默认未明确设置为特殊；特殊分裂可能失去类别 | `{新建}` 及其子链始终为 `special` | `createEmptyTempSection()` 写入 `tempKind: "special"`；分裂读取父 `tempKind` 并继承 |
| 尺寸/颜色 | 外观已有 `sizes.specialTemp`、`colors.specialTemp`，由 `tempKind/source` 判断 | 特殊栏目及其所有子链使用该独立配置 | 以 `tempKind` 为主，`source` 仅保留为来源说明和创建入口分类 |
| 画布来源徽标 | 优先读 `originPermanent`，标签只作为回退 | 不再显示 | 标题栏不再渲染来源徽标；`label` 已是栏目唯一显示语义 |
| 删除永久栏目副本 | 删除时扫描临时栏目并删除匹配的 `originPermanent.copyId` | 临时栏目是独立快照，不做反向清理 | 删除 `__clearTempSectionOriginForDeletedPermanentCopy()` 和调用点 |
| 侧栏排序 | 读取 `sequenceNumber` 排序/分类 | 常规栏目按链式标签自然排序，特殊栏目按标签自然排序 | 解析 `A-1-2` 为可比较片段；先按 `tempKind` 分组 |
| 搜索索引 | 索引 `sequenceNumber`；多栏目模式读取 `originPermanent.displayIndex` 并以单字母标签回退 | 索引 `label`；仅常规栏目解析完整字母前缀 | 删除数值字段；仅 `tempKind: "regular"` 的 `A-1` / `AA-1` 链标签可进入永久栏目多列布局 |
| 导入 | 读取两个字段；缺失时存在不同路径的隐式回退 | 两字段完全不参与导入；外部无 label 数据可导入 | 只读 `label`、`source`、`tempKind` 与内容；没有 label 时写入固定协议值 `{unknown}` |
| BCS / 导出 | `bcs:section:*` 和单栏目 JSON 在 `items` 后追加两字段 | 任何新写入的协议都没有两字段 | 从协议构建、快照构建、恢复对象和导出构建中移除写入；读取端丢弃旧字段 |

## 功能改造清单

| 功能 | 当前涉及点 | 改后行为 | 验收结果 |
| --- | --- | --- | --- |
| 空白新建 | `createEmptyTempSection()` 分配序号，无标签时不是明确特殊栏目 | 创建 `{新建}` 特殊栏目；重复时 ID 去重，不改变显示标签 | 使用特殊尺寸/颜色；导出只有 `label: "{新建}"` |
| 特殊栏目分裂 | `getSplitTempSectionLabel()` 可基于父标签，但创建路径未保证继承类别 | `{导入}` -> `{导入}-1` -> `{导入}-1-2`，继承 `special` | 子栏目仍使用特殊外观且目录仍在特殊栏目组 |
| 常规栏目分裂 | 继承父标签，同时复制永久来源元数据 | 只继承父标签和所需视觉属性 | `A-1` -> `A-1-1`，导出没有来源字段 |
| 永久栏目拖入 | 上下文构造 `originPermanent`，随后用它生成标签 | 上下文只在创建阶段选择 A/B 标签族 | 创建后不保存永久栏目副本 ID；`A-2` 仍正确分配；副本删除/重排不改变临时栏目 |
| HTML/JSON 书签导入 | 创建特殊导入栏目但写入序号 | 创建 `{导入}` 特殊栏目 | 导入、分裂、再次导出均无隐藏字段 |
| 拖入/搜索/批量/粘贴/快速添加 | 多个入口都递增序号 | 每个入口提供显式特殊标签/来源 | 不再存在全局临时栏目序号 |
| ID 迁移与连线 | 旧 ID 迁移会从 `label + sequenceNumber` 重建 ID | 仅用标签重建；已有合法 ID 保留 | 连线、item `sectionId`、折叠状态不丢失 |
| 目录 | `getTempSectionLabel()` 与 `isSpecialTempSection()` 读取序号 | 只读取显式标签和 `tempKind` | `{新建}-1` 显示、排序、分类正确 |
| 搜索 | 标签、序号、来源列同时索引 | 标签作为唯一栏目索引键 | 按 `A-1`、`AA-1` 搜索和多栏目布局正确；特殊栏目无伪来源列 |
| 副本删除 | 清理 `originPermanent` 以避免过时 #A/#B | 无关联可清理 | 删除永久副本不改变任何临时栏目内容或标签 |

## 当前删除行为与第三方编辑风险

当前删除一个临时栏目时，代码**不会**修改其他栏目的 `sequenceNumber`；只有临时栏目全部清空时才将全局序号计数器重置。因此“删除一个栏目导致现有其他栏目统一改号”不是当前行为。

真正的问题是 `sequenceNumber` 仍是隐藏输入。第三方 JSON 修改、删除或填写该字段后，导入、加载和后续新建会据此改变运行时行为：

| 外部操作 | 当前结果 | 移除后的结果 |
| --- | --- | --- |
| 删除某个栏目 | 保留其他栏目序号；仅空画布时重置全局计数器 | 保留其他栏目 `label` 和 `id`；没有序号状态可重置 |
| 修改某个 JSON 的 `sequenceNumber` | 导入路径可能用它恢复栏目字段、决定 ID 回退，并影响后续创建的计数器上界 | 忽略该旧字段；只读取 `label`、`tempKind`、`source` 和内容 |
| JSON 省略 `sequenceNumber` 但有 `label` | 某些路径从标签反推序号，另一些路径使用当前全局计数器 | 只接受现有 `label`，不产生或推导序号 |
| JSON 省略 `label` | 当前会因入口不同而走标题、来源或序号回退 | 保留类别/来源，统一补 `{unknown}`；不会影响其他栏目 |

这正是移除的价值：第三方只需修改栏目自己的显式字段。当前版本不会在删除 A 后改写 B、C，但 A 的隐藏序号仍会参与 A 的排序/搜索以及后续栏目的分配；移除后，任何栏目都不再受这类隐藏输入影响。

## 最小影响实施路径

本次目标是**同时删除** `originPermanent` 与 `sequenceNumber`，但不借机重做栏目 ID、画布连线、文件格式或历史数据。采用下列最小影响边界：

| 边界 | 最小影响做法 | 明确不做的事 |
| --- | --- | --- |
| 本地存储与导入输入 | 读取时直接忽略两个字段；已有 `label` 原样保留 | 不根据旧 `originPermanent` 或 `sequenceNumber` 推导、恢复或兼容任何历史关系 |
| 无 label 的输入 | 统一补 `label: "{unknown}"`，原 `source` 与 `tempKind` 原样保留 | 不尝试猜测 A/B 家族、创建时间或历史层级 |
| 新建与导入 | 创建时一次性生成/补齐显式 label，随后仅传递 `label`、`source`、`tempKind` | 不创建或恢复全局序号 |
| 永久栏目拖入 | 仅在拖拽当次读取永久栏目/副本，以选择 A/B 标签族 | 不把 copyId、displayIndex 或永久关系写进临时栏目 |
| 特殊栏目 | `{新建}`、`{导入}` 等显式标签；分裂从父 label 追加 `-N` | 不要求特殊标签全局唯一 |
| ID / item / edge / 滚动状态 | 保留既有 `id` 与所有引用；只有现有旧 ID 迁移仍需要时才走引用重写 | 不因移除字段批量改 ID、重写 edge 或重置折叠/滚动状态 |
| 协议版本 | 继续写 `schemaVersion: 2` | 不为可选字段删除升级 schema |
| 本地存储与运行时读取 | 读取时忽略两个字段；任何新建及重新序列化写入都不包含它们 | 不做升级时主动清洗，不保留旧字段回退或历史状态迁移 |

实现时只需要一个中心化的“确保显式标签”规则，而不是在每个 UI 调用点复制复杂判断：

1. 常规创建：拖拽上下文在内存中决定 `A-N`、`B-N`，生成后只保存 label。
2. 分裂创建：父栏目 label 加 `-N`；继承父 `tempKind`，特殊父栏目保持 `special`。
3. 特殊创建：入口提供固定 label，例如 `{新建}`、`{导入}`、`{拖入}`。
4. 外部导入/拉取：有 label 就直接使用；无 label 统一使用固定协议值 `{unknown}`。
5. 所有后续显示、目录、搜索和 ID 回退只读 label；不再读取两个旧字段。

这条路径的核心是“直接忽略、严格新写入”：无需让第三方补序号，也不因旧字段缺失或篡改而重新编号其他栏目。

## 既有数据清理规则

本次不执行旧字段关系恢复，也不利用旧字段推导标签：

1. 已有非空 `label`：保留标签，直接删除两个字段。
2. 无 `label`：无论是否带旧字段，一律补固定协议值 `{unknown}`；保留原 `tempKind` 与 `source`。
3. 子栏目仅在新分裂操作时从父 `label` 生成 `父标签-N`，不对旧数据猜测父子关系。
4. 导入、加载、备份、同步和保存的运行时对象均不得保留两个字段。

字段清理不得因为标签变化而覆盖现有 `id`、item `sectionId`、Canvas edge、折叠/滚动 key。只有当前已有的明确旧 ID 改名规则需要运行时，才通过现有引用重写流程处理。

## 建议的协议示例

常规临时栏目：

```json
{
  "format": "bookmark-canvas-section",
  "schemaVersion": 2,
  "sectionType": "temporary",
  "id": "temp-section-A-1",
  "label": "A-1",
  "title": "Research set",
  "tempKind": "regular",
  "source": "",
  "descriptionMd": "A sandbox bookmark tree.",
  "items": []
}
```

特殊临时栏目及其分裂：

```json
{
  "format": "bookmark-canvas-section",
  "schemaVersion": 2,
  "sectionType": "temporary",
  "id": "temp-section-导入-1",
  "label": "{导入}-1",
  "title": "Imported bookmarks - refined",
  "tempKind": "special",
  "source": "import-json-bookmarks",
  "descriptionMd": "Refined from the imported temporary section.",
  "items": []
}
```

## 验收矩阵

| 场景 | 必须验证 |
| --- | --- |
| 新建空白栏目 | 标签为 `{新建}`，`tempKind` 为 `special`，特殊外观生效，无两个旧字段 |
| 新建空白栏目后分裂两次 | `{新建}-1`、`{新建}-1-2`，均为 `special` |
| 导入 JSON 后分裂 | `{导入}`、`{导入}-1`，导出与 BCS 均无两个旧字段 |
| 从主永久栏目与永久副本拖入 | 分别生成正确 A/B 标签族；删除副本后临时栏目不被改变 |
| 带旧字段的栏目导入 | 忽略两个旧字段；保留已有 label，无 label 时补 `{unknown}`；保存后旧字段被清除 |
| 无字段的第三方 JSON | 只要有 `label` 即可导入；无标签时统一补 `{unknown}`，并用 `id` 保证引用不冲突 |
| 侧栏与搜索 | 常规/特殊分类、链式排序、`AA-1` 搜索和多栏目判断正确；同名特殊栏目按 `id` 保持可定位 |
| 连线与刷新 | 字段清理或既有旧 ID 改名后，item、edge、折叠/滚动状态仍指向正确栏目 |
| 剪贴板、指针拖拽、书签树拖拽、GitHub 包拉取 | 间接创建/恢复临时栏目后，label、`tempKind`、特殊外观正确，运行时/BCS/导出 JSON 均不含两个字段 |
