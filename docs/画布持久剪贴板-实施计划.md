# 画布持久剪贴板实施计划

状态：待实施  
范围：画布内书签、文件夹、临时栏目节点、批量选择与画布文本的复制/剪切历史。

## 目标

将现有仅存在于单个页面内存中的复制/剪切状态，升级为画布级、可持久保存的剪贴板历史：普通画布页与所有侧边栏共享同一份记录，刷新或重启后仍可继续使用。

每一份记录必须保存独立快照。原临时栏目、书签或文件夹在复制/剪切后被删除，不能影响后续从剪贴板记录重新复制或粘贴。

## 已确认的产品规则

1. 默认保留最近 7 条记录；用户可在剪贴板设置中调整数量，建议输入范围为 1–50。
2. 剪贴板历史使用扩展本地持久存储，而不是只使用 `BroadcastChannel` 或页面内存。
3. 所有已打开或之后打开的普通画布页、侧边栏画布页都显示同一份历史；通过存储变更事件自动同步。
4. 每条记录左侧始终显示复选框，右侧提供单条删除按钮。
5. 选中一条或多条记录后，面板右上角显示“复制（n）”与“取消”。
6. 点击“复制（n）”会以所选记录的快照创建新的当前复制内容，并覆盖当前待粘贴的复制或剪切内容。
7. 新的复制覆盖待粘贴剪切后，旧剪切不再具有“移动源对象”的资格；它保留为历史快照，未来只能重新作为复制内容使用。
8. 复制可重复粘贴，不因首次粘贴清空。
9. 剪切仅在它仍是当前待粘贴内容时执行一次移动；成功后保留历史快照，但后续重用按复制处理。
10. 每条记录在列表中仅预览前两项，其余内容显示汇总，如“+ 8 个书签 · 3 个文件夹”。
11. 清空按钮清除全部剪贴板历史；应保留二次确认，避免误删。

## 界面方案

### 入口

在标题栏“设置”菜单中，于“画布管理”上方新增一级“剪贴板”入口（图标：`fa-clipboard`）。点击后打开独立的 `canvasClipboardModal`，不将剪贴板塞入既有画布管理弹窗。

### 剪贴板面板

顶部区域：

- 标题：剪贴板。
- 右侧：设置（容量）、清空、关闭。
- 当存在勾选项时，替换或补充显示“复制（n）”“取消”。

记录卡片：

- 左侧复选框。
- 操作标签：复制、剪切、文本、批量复制等。
- 中间摘要：前两项书签/文件夹标题，或前两行文本；附创建时间。
- 超出预览内容的数量汇总。
- 右侧单条删除按钮。
- 当前待粘贴记录使用清晰但不过度醒目的“当前”状态。

### 勾选复制

1. 用户直接勾选任意一条或多条历史记录。
2. 点击“复制（n）”。
3. 单选：将该记录快照作为新的当前复制内容；不改变原历史记录。
4. 多选：按用户在列表中的顺序合并所选快照，创建一条新的“批量复制”记录并设为当前内容。
5. 点击“取消”仅取消当前勾选，不影响历史或当前待粘贴内容。

## 数据模型

建议使用独立的扩展本地存储键，避免与画布主体数据混杂：

```js
// bcs:clipboard-history
{
  version: 1,
  limit: 7,
  activeEntryId: 'clipboard-entry-id-or-null',
  entries: [
    {
      id: 'unique-id',
      kind: 'structured' | 'text',
      originalOperation: 'copy' | 'cut',
      activeOperation: 'copy' | 'cut' | null,
      cutState: 'pending' | 'consumed' | 'superseded' | null,
      createdAt: 0,
      updatedAt: 0,
      summary: {
        bookmarkCount: 0,
        folderCount: 0,
        textPreview: '',
        previewItems: []
      },
      payload: [],
      sourceRefs: []
    }
  ]
}
```

说明：

- `payload` 是深拷贝后的权威数据，粘贴不能依赖 `sourceRefs`。
- `sourceRefs` 只用于当前剪切首次粘贴时尝试移动/删除源对象。
- `activeEntryId` 代表当前右键菜单与快捷键可粘贴的内容。
- `cutState` 防止被新的复制覆盖后，旧剪切仍错误移动已经变更或删除的源对象。

## 复制、剪切与粘贴语义

### 结构化内容

现有单项与批量入口统一改为调用一个“写入剪贴板历史”服务：

- 永久书签/文件夹复制与剪切。
- 临时栏目节点复制与剪切。
- 批量永久节点复制与剪切。
- 批量临时节点复制与剪切。
- 混合批量复制。

服务在动作发生时立即序列化完整 payload；不得在粘贴时重新从 DOM、临时栏目或 Chrome 书签 API 读取内容作为前提。

### 剪切落位

1. 当前活动记录为 `cut + pending` 且源对象仍完整存在：优先执行移动，保留原有 ID 与排序语义。
2. 源临时栏目、节点或永久书签已被删除：跳过移动，直接由 `payload` 创建目标内容。
3. 批量操作逐项处理；任意已不存在的源项走快照回退，不能导致整批失败。
4. 剪切成功后，将该记录标记为 `consumed`，并取消当前活动剪切状态。
5. 任何新的复制激活时，旧的 `pending` 剪切标记为 `superseded`；以后从它恢复时只创建复制，不再移动源对象。

### 文本内容

在 `history.html` 的画布内容范围监听原生 `copy` 事件，且不阻止浏览器原有复制行为。

应捕获：

- 空白栏目中的文本选区。
- 永久/临时栏目说明。
- Markdown 卡片正文和画布笔记。

不应捕获：

- 设置弹窗、搜索框、标题输入框等普通界面控件。
- 扩展外的网页、浏览器或桌面应用内容。

文本历史记录被勾选并点击“复制”后，写回系统剪贴板（`navigator.clipboard.writeText`，必要时提供兼容回退），以便粘贴到说明、笔记和其他文本输入框。

## 存储与跨页面同步

1. 以 `chrome.storage.local` 为主存储；项目无扩展 API 时可降级至 `localStorage`。
2. 每个 `history.html`（普通画布页与侧边栏 iframe）在启动时加载剪贴板状态。
3. 所有页面监听 `chrome.storage.onChanged` 对该键的变更并刷新面板、当前粘贴状态与剪切视觉标记。
4. 写入采用统一读—改—写队列，并附带 `updatedAt`/版本，避免多个侧边栏同时复制时丢失更新。
5. 新记录写入后按 `limit` 截断最旧记录；降低容量时也立即截断最旧记录。
6. 数据只在扩展本地存储中保存，不上传、不同步至云端，也不尝试读取操作系统剪贴板历史。

## 验收用例

1. 复制一个临时栏目书签，删除原临时栏目，再粘贴：成功创建副本。
2. 剪切一个临时栏目节点，删除原栏目，再粘贴：由快照成功创建目标内容。
3. 批量剪切多个临时节点，删除其中部分源节点，再粘贴：存在的节点移动，不存在的节点由快照创建，整批不失败。
4. 任意复制内容连续粘贴三次：均成功，记录仍存在。
5. 剪切后先执行新的复制：旧剪切不再移动任何源内容；其历史快照可重新作为复制使用。
6. 两个普通画布页与两个侧边栏同时打开：任一页的新记录会出现在其他三个界面。
7. 关闭并重新打开画布页或重启扩展：剪贴板历史与容量设置仍存在。
8. 容量为 7 时新增第 8 条记录：最旧记录被移除。
9. 文本选区复制出现在历史中；从历史重新复制后可粘贴到说明/笔记输入区。
10. 设置输入非法容量时回退到有效范围，清空全部时必须经过确认。

## 非目标

- 不读取或展示 macOS/Windows 的系统剪贴板历史。
- 不监听扩展外网站、其他浏览器标签页或其他桌面应用的复制/剪切。
