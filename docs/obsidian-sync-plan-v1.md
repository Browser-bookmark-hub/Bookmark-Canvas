# Obsidian 双向同步计划书（V1）

> 返回文档索引：[docs/README.md](./README.md)

## 1. 项目目标

- 在不破坏现有 Bookmark-Canvas 体验的前提下，实现与本地 Obsidian 的双向同步。
- 采用“内容态同步、视图态独立”的策略，保证功能清晰、边界可控。
- 冲突处理采用 `Last-Write-Wins`（最新修改为当前版本），保证最终一致性。

## 2. 同步范围（白名单）

### 2.1 同步内容（V1 必做）

- 永久栏目数据（含说明文本、颜色等持久字段）
- 临时栏目数据
- 空白栏目（Markdown 节点）
- 节点布局（位置、尺寸）
- 连接线（from/to/label/color 等）
- 必要元信息（`version`、`updatedAt`、`clientId`）

### 2.2 不同步内容（V1 明确排除）

- 文件夹展开状态
- 滚动位置
- 视角定位（pan/zoom）
- hover、选中态、拖拽中间态等会话 UI 状态

## 3. 技术路线

- 采用线路 B：`Obsidian Local REST API`。
- Obsidian 侧提供本地 API（本机回环地址 + API Key）。
- 扩展侧实现同步适配层，负责推送、拉取、重试和冲突决策。

## 4. 数据模型与版本规则

### 4.1 统一同步对象（建议）

```json
{
  "version": 102,
  "updatedAt": 1760000000000,
  "clientId": "canvas-sidepanel-xxx",
  "payload": {
    "sections": [],
    "mdNodes": [],
    "edges": []
  }
}
```

### 4.2 版本判定

- 先比较 `version`，大的为新版本。
- `version` 相同时比较 `updatedAt`。
- 仍相同则比较 `clientId`（仅用于稳定打破平局）。

## 5. 同步流程

### 5.1 浏览器 -> Obsidian（推送）

1. 本地内容变更后，仍先走现有持久化入口（`saveTempNodes()`）。
2. 将白名单字段序列化为同步对象。
3. 经防抖队列（建议 300~800ms）后推送到 Obsidian 本地 API。
4. 推送成功后更新本地同步游标（lastAckVersion）。

### 5.2 Obsidian -> 浏览器（拉取）

1. 定时轮询远端版本（建议 1~3 秒）。
2. 若远端版本更新，则拉取最新同步对象。
3. 应用到 `CanvasState`，并触发现有跨页面同步机制。
4. 仅应用白名单字段，避免污染本地视图态。

## 6. 冲突策略

- 默认策略：`Last-Write-Wins`。
- 为避免静默覆盖，保留冲突日志（记录被覆盖版本的摘要）。
- 若未来需要可升级为“手动合并/以我为准/以远端为准”。

## 7. 安全与稳定性

- 仅允许访问本机 API 地址（回环地址）。
- API Key 存储在扩展安全存储中，不写入导出文件。
- 所有网络错误进入重试队列，使用指数退避。
- Obsidian 离线时保持本地可用，恢复后补偿同步。

## 8. 里程碑计划

### M1：协议冻结（1~2 天）

- 确认白名单字段
- 确认版本规则与冲突规则
- 完成同步对象 schema 文档

### M2：单向推送（2~3 天）

- 完成扩展 -> Obsidian 推送链路
- 完成失败重试与错误提示

### M3：反向拉取（2~3 天）

- 完成 Obsidian -> 扩展拉取链路
- 完成本地状态回灌与多页面广播

### M4：稳定性强化（1~2 天）

- 冲突日志
- 离线补偿
- 压测与节流参数调优

### M5：验收（1~2 天）

- 多窗口/多标签页/侧边栏联测
- 重启恢复一致性验证

## 9. 验收标准

- 双端任一侧修改后，另一侧在目标时间内可见（例如 <= 3 秒）。
- 多窗口并发操作后，内容态最终一致。
- 断连恢复后无持久内容丢失。
- 展开/滚动/视角等视图态保持独立，不被跨端覆盖。

## 10. 后续（V2 可选）

- 增量 patch 同步（降低传输成本）
- 同步状态面板（最后同步时间、失败次数、待同步队列）
- 冲突手动处理 UI（以我为准 / 以远端为准）
