# Agent 树状上下文读取与模板增强计划

> 状态：模板、README 与 Bookmark Research 插件说明已实施；模板握手只盘点宿主能力，§3 核心红线负责大文件读取与无插件时按 ID 遍历 JSON 树、回溯父路径，插件 API 细节留在插件文档。JSON 示例检查及插件 47 项相关测试通过；另已用实际完整包验证插件查询与本地解析结果一致。步骤 4 的真实导出包手动体验仍由用户执行。模板/README 按当前导出形状说明占位字段，不代表运行时存储方案已决定或已清洗。存储方案仍见[临时栏目存储协议精简计划](./临时栏目存储协议精简计划.md)，与本计划独立。

## 1. 用户目标与本轮范围

用户希望 Agent 能识别临时栏目中的书签、文件夹及树形关系，精准读取一个节点的祖先、相关后代和卡片上下文，在分析或修改少量条目时避免将整包或整个大栏目送入模型上下文。

临时条目现有的 folder.url 空字符串与 bookmark.children 空数组属于统一对象形状留下的空占位，不是有效网址或子树。它们增加少量文本，但不妨碍正确的按类型解析。树状上下文读取是独立能力，不以这些属性是否存在为前提。

| 工作项 | 当前安排 |
|---|---|
| 中英文 AGENTS 模板 | 补足临时条目按 type 判型、空占位含义、局部读取流程与实际案例；核对已有说明，避免重复堆叠规则 |
| 三处 README | 同步简明规则；选择保留空值时展示空占位，选择精简时与已实现的新导出对齐 |
| 书签研究插件 | 复用已存在的栏目、节点、祖先和文件夹范围查询；补足使用说明与验证案例。只有发现可复现能力缺口才提出对应改动 |
| BCS、运行时、复制粘贴、导入导出、备份、GitHub 同步 | 属于独立的存储方案选择；本计划不把任何读取优化写成清洗已完成或清洗被取消 |
| 用户旧数据 | 两种存储选择下都按类型理解；Agent 读取不顺带改写原文件。迁移行为仅由独立精简计划定义 |

两份模板指 Bookmark-Canvas-main/history_html/transfer_AI_sync/AGENTS_template/ 下的 AGENTS_template_zh.md 与 AGENTS_template_en.md；三处 README 指 README.md、docs/README/README.zh.md、Bookmark-Canvas-main/README.md。插件说明修改位于本机 Bookmark Research 源码 checkout 的双语 package-semantics 文档；它不是插件发布或安装副本更新的证明。

### 1.1 安全红线：工具先行，按需送入模型上下文

中英文模板须在开头握手中保留工具选择和大文件读取要求，并在“核心红线”中加入同等约束：

> **禁止将整包、大栏目全文或多卡累计的大量内容一次性倾倒进模型上下文。先识别宿主可用工具，优先调用书签研究插件的公开接口；无插件则用本地 JSON 解析工具，按目标卡片、节点 ID 和任务范围提取必要的祖先、后代、元数据与画布关系。工具可在本地完整解析文件，但只向模型返回必要记录、摘要与分页信息。不得把部分结果冒充完整遍历，也不得把精简查询记录整项覆盖回原文件。**

很小且累计体量适合当前任务的文件可直接阅读；不能以“JSON 可解析”“临时栏目”或“锚点包含该卡片”为理由整包展开。用户要求完整范围分析时，工具可以完整遍历，模型按批次接收结果和汇总，保持已读/未读范围可追踪。

以上是两种存储选择都必须遵守的工作方式，与是否删除空占位无关。

## 2. 临时条目的读取规则

### 2.1 以显式 type 区分节点

| 临时条目类型 | 有效内容 | 现有空占位的含义 | Agent 处理 |
|---|---|---|---|
| type: folder | title、children、身份及内嵌元数据 | url: 空字符串不表示链接 | 按 children 读取后代；不得因存在 url 属性就判为书签 |
| type: bookmark | title、url、身份及内嵌元数据 | children: 空数组不表示容器 | 按 url 读取链接；不得因存在 children 属性就判为文件夹 |

空文件夹的 children: [] 是有效容器状态，必须与书签上的空占位区别。已有字段按授权范围处理，不因一次问答、整理或局部编辑顺便清理整棵树的空属性；也不要求将已省略的无意义字段补齐。选择保留现状时，模板解释当前导出形状；选择精简时，写端按独立计划省略冗余字段。两种情况下读端都以 type 为准，不新增新旧字段版本分支。

临时 item 的 type 规则不能套用到所有 JSON 对象：永久树节点通常按 URL 和树结构适配；.canvas 的 type: file/group/text 是画布实体类型，与条目的 folder/bookmark 分属不同层。永久元数据来自 identityMap，临时 tags、note、noteColor 内嵌在 item 上。

遇到缺失或非法 type、bookmark 携带非空 children、folder 携带非空 url 等冲突，报告具体节点与字段并保留原数据，不自动猜测改型或丢弃子树。空占位说明不构成对异常非空字段的自动修复授权。

### 2.2 选择保留空值时的最小识别例子

下面只演示节点结构，省略身份和元数据，不是可直接导入的完整栏目文件：

```json
{
  "title": "资料",
  "type": "folder",
  "url": "",
  "children": [
    {
      "title": "示例网站",
      "type": "bookmark",
      "url": "https://example.com/",
      "children": []
    }
  ]
}
```

该对象只有一个文件夹和一个书签。folder.url 与 bookmark.children 只作空占位；识别树形结构依据 type 与有效 children，不依据两个属性是否存在。

### 2.3 两类临时栏目示例的条件同步

这里的“两类”指中英文模板中已有的普通链式临时栏目（tempKind: regular）和特殊临时栏目（tempKind: special），两种示例都要核对：

- **选择保留两个空值**：在两类示例的 folder 节点加入 url: 空字符串，在 bookmark 节点加入 children: 空数组；说明它们是现有构造器的空占位。将通用 type 规则集中解释，不在特殊栏目重复整段规则。
- **选择删除两个空值**：两类示例均省略 folder.url 和 bookmark.children，空文件夹仍保留 children: []；以实际交付的导出行为为准，同步三处 README。
- 两种选择都保留原有 ID、sectionId、tags、note、noteColor 说明；已有包的空占位不作为类型、损坏或删除依据。不可先修改示例就宣称运行时协议已切换。

## 3. 局部上下文的读取流程

1. **定位卡片**：从用户给出的栏目、节点 ID 或锚点出发，解析 .canvas 的实际文件引用，得到目标栏目文件。锚点视野只用于筛选候选卡片，不表示所有相交卡片的全部条目都需要进入上下文；置顶切片也不能当作真实视野坐标。
2. **先读概况**：获取栏目标题、说明、条目规模与文件夹目录。多卡任务同时控制累计返回量，不能把每张卡片分别算作小文件就全部展开。
3. **定位树节点**：按 source_id + section_id + item_id 精确定位。标题、label 或 URL 可能重复，不可作为唯一身份。
4. **补充必要上下文**：读取目标节点、祖先链及任务涉及的后代；比较同级项目时再读取父文件夹范围并按 parent_id 筛选。需要解释卡片用途时补充 descriptionMd、相关文本、组与有向连线，而不是推断空间接近等于内容归属。
5. **按需分页**：显式指定 limit、offset、compact；返回总数和 next_offset，明确已读范围。少量样本不能代表整棵树已审阅，用户要求完整范围时继续分页至完成。
6. **编辑前回读**：查询索引用于定位和理解；写入前从当前原文件提取目标并核对身份与上下文，按授权范围修改，保留其他条目和未知字段。写后刷新同一来源索引再查询。

工具在本地完整解析文件与模型接收完整文件是两回事。JSON 提供可解析结构，脚本或插件负责选择与裁剪；格式本身不会自动节省上下文。

### 3.1 已有书签研究工具及边界

| 需求 | 当前公开工具 | 使用边界 |
|---|---|---|
| 栏目目录及数量 | get_context(collection="sections", compact=true) | 返回栏目摘要，不附整棵 tree/items；compact 会省略 description_md，需要说明时另取 |
| 一个栏目的文件夹目录 | search_bookmarks(section=..., item_types=["folder"]) | 分页列目录；同时保留 parent_id、path、position，不能仅按标题拼树 |
| 一个节点及其祖先 | get_context(section=..., item_id=..., collection="items") | 返回目标与 ancestors；不自动附全部后代 |
| 文件夹及后代 | search_bookmarks(section=..., folder_id=..., item_types=["folder", "bookmark"]) | 返回范围内的扁平节点记录，包含所选文件夹本身；按 parent_id 和 position 理解层级与顺序 |
| 查标题、网址、笔记或标签 | search_bookmarks(targets=..., section=... 等) | 字面匹配，不等于语义理解；未命中需核对别名及范围 |
| 卡片的组、连线、相关节点 | get_context 的 nodes/groups/edges/related_nodes 等集合 | 分集合分页；当前没有直接的 region/nearest-neighbor 查询参数 |

现有接口没有一个通用的“任意子树原样 JSON + 指定深度 + 同级窗口”参数。已有节点、祖先和范围检索足够完成基础局部读取；需要直接子项、同级范围或原样嵌套子树时，可在返回记录中筛选，或用本地脚本从源文件提取。不能把本计划写成这些高级参数已经存在。

临时节点按 type 解析的能力已在插件导入器中存在；永久 identityMap 与树节点的元数据关联也已存在。模板应教 Agent 使用这些能力，而不是重复发明索引。

### 3.2 已实测的使用案例

核验来源：现有 source_id 为 canvas-20261027-template-eval 的已保存快照，数据日期为 2026-10-27；refresh=false 读取保存索引，不代表已核对当前浏览器或原目录的最新内容。全部为本地查询，未联网、未修改原包。

- 包内 5 个栏目、335 个书签实例；A-3 栏目包含 83 个书签。
- 在 A-3 中定位文件夹 GPT OSS 20b / 120b，ID 为 tempId_20261027_hash_6i171v2。
- get_context 返回其祖先链：开源(主模型｜框架｜训练方法等) #公司 → 国外开源 open source #开源 #公司 → OpenAI。
- 对该文件夹调用 search_bookmarks，限制 folder 与 bookmark、limit=3，返回 total=8、3 条记录、next_offset=3。只获得当前页面，不把整个 A-3 或数据包送入模型上下文。
- 永久栏目也已实测指定节点读取，获得目标书签及祖先；并非只有临时 item 才能局部查询。

对应调用参数示例（先定位实际 source、section 与 item ID；此处 ID 仅用于复现实测）：

```json
{
  "source_id": "canvas-20261027-template-eval",
  "section": "temp-section-A-3",
  "item_id": "tempId_20261027_hash_6i171v2",
  "collection": "items",
  "compact": true,
  "limit": 1,
  "refresh": false
}
```

上例用于 get_context。读取所选文件夹范围时调用 search_bookmarks：

```json
{
  "source_id": "canvas-20261027-template-eval",
  "section": "temp-section-A-3",
  "folder_id": "tempId_20261027_hash_6i171v2",
  "item_types": ["folder", "bookmark"],
  "compact": true,
  "limit": 3,
  "offset": 0,
  "refresh": false
}
```

refresh=false 只用于明确选择保存快照的场景；live 来源应按任务核对新鲜度，原包编辑后更新同一 source_id。模板正式案例可缩短为操作步骤，不能机械复制这里的历史 ID。

插件查询行自身也可能用统一字段展示 folder 的 url: 空字符串；这属于查询返回结构，不代表它把原始 JSON 重新写回了。数据包协议、检索返回结构与模型上下文摘要应分别理解。

### 3.3 没有插件时

使用 Python、Node.js 或 jq 解析原 JSON，临时栏目从 items 开始，永久栏目从 tree 开始；按节点 ID 定位，记录父子、祖先和同级顺序，只返回任务需要的字段与分支。永久元数据需按 identityMap 的 syncId 关联，不能只提取 tree 就宣称标签笔记齐全。

小文件可以直接阅读；大栏目或多卡累计数据应先统计再提取。脚本能够完整读写源文件，但模型上下文仅接收目标、必要祖先/后代、摘要与未展开数量。完整读取是否合适由实际体量和任务决定，不设置未经验证的通用字节阈值。

## 4. 实施步骤与验收分工

### 步骤 1：两份模板说明对齐

- 在临时栏目通用规则中解释 type、两个空占位与空文件夹，不将永久树判型规则混入。
- 按 §2.3 同步普通/特殊两类示例：保留方案加入占位与解释，精简方案按新导出省略占位；不得把示例差异写成格式损坏或要求用户全库补齐。
- 开头握手只盘点可用插件、MCP/API、CLI、文件与代码工具，不在此阶段读取数据。大文件读取、禁止整包进入上下文及无插件时按 ID 定位 JSON 节点、回溯父路径等规则集中写入核心红线；模板不复制 bookmark-research 的 API、参数或调用示例，插件的具体能力与用法由插件自身文档负责。
- 保留现有身份、元数据、授权及文件路由规则；不因本项顺便改变浏览器操作或跨类型复制身份策略。

### 步骤 2：README 与插件使用说明核对

- 三处 README 用同一条临时 type 规则解释空占位，与两份模板示例一致。
- Bookmark Research 插件说明单独记录其已验证能力与具体调用方式，包括 get_context 的祖先链、search_bookmarks 的 folder_id 子树和分页边界；这些 API 细节不放进 AGENTS 模板。
- 先用实际小样本核对现有解析器；正常空占位有无不应影响类型与节点数。没有发现缺口时无需改插件实现，不以新增工具数量作为完成标准。

### 步骤 3：实施者必要检查

- 对照模板和 README 的 JSON 示例，确认语法、字段含义与实际导出一致；对比中文与英文规则。
- 用隔离样本核对 folder.url 为空字符串、bookmark.children 为空数组，以及省略这两个占位时，临时类型与层级识别一致；空 folder 保持 folder。
- 核对永久 metadata 关联、重复标题/URL、祖先路径和文件夹范围查询；分页报告总数、已读数及未读范围，不能假称全量验收。
- 模板如涉及写入操作，要求按当前原文件回读；不把精简查询记录当作可覆盖原始对象的完整副本。
- 如确需改插件解析或查询代码，再补有针对性的回归检查；纯说明修改不新增迁移脚本或全库扫描测试。

### 步骤 4：用户手动体验验收

用户在浏览器导出/推送后，自行核对新包指南内容，并选择真实锚点或大栏目提出问题，例如“只看 OpenAI 文件夹下面的 GPT OSS 资料，结合上层分类解释用途”。观察 Agent 是否定位目标、读取祖先及必要后代、说明未读范围，且未将整包输入上下文。

本步骤由用户执行；实施者交付具体操作与预期，未执行标记待用户验证。现有快照的工具实测不能代替新导出包、最新插件或浏览器联调验收。

## 5. 当前方案的限制

1. 持久化空占位是否保留取决于独立存储选择；本计划交付的是定位、树状理解和上下文控制，不宣称已完成存储清洗。
2. 正确使用工具能控制模型接收量，但原始文件解析、索引构建和刷新仍有本地开销。不能承诺零开销，也不能把清洗后的启动性能收益记到本方案上。
3. 插件检查结构和提供关系记录，不自动理解所有分类意图；研究结论仍需结合实际标题、说明、标签、笔记和关联卡片。
4. 异常非空字段、无效 type、身份冲突不能仅靠“空占位正常”解释。插件当前有部分校验，但不是所有浏览器行为或协议约束的完整验证器。
5. 本计划本身不引入数据迁移或启动清洗；若同时选择精简方案，按该计划另行核验备份协调、旧数据处理与业务回归，不能用工具读取成功代替这些检查。
